# 证据整理失败后的恢复操作

进入 [科研工作台](https://scientific-agent.panghuer.top/)，选择原研究项目。可以保留失败任务与已有成果继续操作，无需新建项目或反复提交同一任务。

## 查看筛选变更前的证据

1. 打开“文献与证据”，找到“已保存的证据版本”。
2. 点击需要的证据版本，核对输入版本、证据摘要、大纲和来源。
3. 使用“复制此版证据与大纲”“下载此版 Markdown”或“下载此版来源关系”留存成果。

标记“基于上一版筛选，待更新”的版本只供历史查阅，不能直接确认后用于新范围写作。保存新筛选后，可点击“更新证据整理与大纲”；重整失败仍保留旧版入口。

需要人工接管时，在同一页面打开“人工整理证据与大纲 → 开始人工整理”。只选择当前纳入的真实来源，填写发现、方法、限制、访问范围和原文位置；仅有摘要时，位置应明确注明“摘要”。补齐章节与证据缺口，核对后点击“保存人工证据版本”。之后仍需完成“确认证据与大纲并写作”；存在缺口时，需明确同意按有限证据成稿。

## 提交可关联的失败诊断

打开页面顶部“任务历史”，或失败提示中的“查看失败任务”，找到本次失败记录。

- 查看具体原因、失败子步骤、错误码、是否可重试及建议操作。
- 点击“复制任务标识”，保留业务“任务 ID”和存在时的“Agent 任务 ID”；尚未提交到 Agent 的任务可能没有第二个 ID。
- 点击“下载脱敏诊断”，将诊断文件和上述标识交给维护人员关联后台记录。

时间信息分别显示创建/提交、实际开始和最近进展；“尚未记录”表示没有可确认的时间，不能据此判断仍在运行。先按诊断建议处理，再决定是否明确重试。

## 将已有 Markdown 恢复稿接入报告流程

等待当前执行任务结束后，直接打开“报告初稿”，即使自动证据任务失败、报告版本仍为 0，也可使用导入入口。

1. 在“导入已有稿件”中点击“导入 Markdown 或手工填写”，选择文件或粘贴正文。稿件上限为 2 MiB UTF-8 字节。
2. 填写来源核对说明与未解决问题，分别确认已核对来源及接受证据缺口，再点击“保存为用户导入报告候选”。
3. 进入“审阅修订”，选择该版本，阅读全文并检查引文。在“人工恢复稿审阅确认”中补充记录，完成两项确认，点击“确认人工恢复稿审阅”。这一步独立于导入时的确认。
4. 在“比较并决定是否采用”中点击“采用此修改候选”。有父版本的候选需先查看与父版本的差异；首次导入没有父版本，无需比较。
5. 如需改正文，先将候选采用为当前工作版本，再用“手工修改并保存新版本 → 编辑此版正文”。修改保存为“人工编辑”候选，继续审阅、比较并明确采用。
6. 打开“定稿导出”，选择已采用的明确版本，核对批注和证据限制，勾选审阅确认后点击“确认为定稿”。可下载 Markdown 和来源记录；草稿也可下载。

导入保留“用户导入”来源，手工修改保留“人工编辑”来源，不会把失败任务改成成功，也不会伪造模型生成或自动证据链校验记录。此类稿件使用人工编辑继续修改，不调用依赖原生模型证据链的章节修订。定稿是项目内的私有版本记录，不代表公开发布、投稿或专家审定。

## 区分资料文件、文献和稿件

“已有资料”中的“文件已读取”只表示系统读到了上传文件；文献来源仍分别记录仅元数据、摘要或全文。将恢复稿上传到“资料”不会增加报告版本，应通过上面的报告导入入口继续审阅。

在对应文件下打开“设置资料类型与内部来源”：

- 恢复稿、综述正文选择“综述或恢复稿件（不计独立文献）”，核对后保存。
- 多来源合集选择“多个来源的资料合集”，逐项填写标题、论文或工程文档类型、文件内实际提供内容及起止行号。行号从 1 开始，结束行包含在范围内；已有来源可填写对应 ID，避免重复计数。
- 例如一个文件含 8 篇论文摘要和 2 份工程文档，应分别声明各项的实际内容，不能因文件读取成功而把 8 篇论文都标为全文。

包内映射是用户对所上传内容的显式声明，不代表系统独立获取或核验了外部论文全文。重复摘录、重复上传和稿件不应增加独立文献数量；文件内来源统计也不能直接与检索文献数相加。
