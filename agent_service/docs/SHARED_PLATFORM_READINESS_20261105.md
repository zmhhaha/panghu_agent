## 平台后续实施

P1 统一共享登录与服务身份合同，验证三业务的拒绝/隔离边界并处理畸形回调。

P2 按实际固定 profile/镜像验证生产准入、永久 UID、输入及候选交接、AppArmor/seccomp、服务账号和代理受限网络。网络拒绝需有健康正控；保留已有安全控制和停止证明。大型渲染镜像的节点放置应服从可测容量，避免再次向所有小磁盘节点预拉。

P3 采用有限、可追溯的实际故障清单；核对 attempt/fence、停止先于槽释放、无重复写入、原成果不变、精确清理和后继成功任务。恢复不延长已冻结 deadline，未知停止保持隔离。

P4 统一执行槽、节点临时空间、业务卷、数据库增长与保留生命周期的容量准入；各业务提供自己的存储和一致性边界。持续备份明确调度、异地、访问保护、保留、失败可见性及恢复目标，并完成独立恢复验证。无需为此统一业务数据库或前端。
