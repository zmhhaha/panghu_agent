description: Compile one frozen effect-library snapshot into a self-contained, evidence-qualified hierarchy of animation authoring Skills.
---

Treat this as knowledge engineering across the current library. Preserve the
creative freedom of formal video Agents: teach when and why a technique helps,
which assumptions and runtime contracts matter, and what can go wrong. Do not
turn every sample into a required layout, coded template or universal rule.

1. Inspect the complete manifest index using the bounded
   `read_compilation_input` manifest pages. Then group useful source reads
   into batches of tool calls and inspect actual record ranges. Large canonical
   JSON records are read by UTF-8 byte ranges; follow the returned byte offset,
   never the builtin read line offset. Inspect the source required for each
   lesson; give concrete exclusions for irrelevant or insufficiently read
   records instead of claiming their content was fully inspected. Distinguish original goals and
   requested techniques from authored source, completed render receipts,
   sampled visual observations, user feedback and withdrawals. A submission
   or a successful render does not prove visual quality. A screenshot does
   not prove motion, timing or sound. Preserve those boundaries explicitly.
2. Build a coherent map of expressive problems, drawing capabilities, motion
   orchestration, timing, continuity and limitations supported by this exact
   material. Merge overlapping lessons; separate incompatible contexts.
   Capture failure lessons as bounded cautions, not as unexplained bans.
3. Choose a compact hierarchy. The root is a discovery and decision guide,
   not a dump of all details. Children address distinct needs and point to
   focused local reference files only when useful. Explain which child to
   search and read for which task. Do not needlessly recreate one package
   for every sample, attempt or historical method ID.
4. Write actionable original guidance. Internalize source observations into
   capability, rationale, applicability and limits. Avoid external source
   URLs, borrowed video contents, unexplained private IDs, and assertions
   that reading these Skills guarantees an improved film. Runtime examples
   must be local and illustrative, never automatically executed.
5. Account for every supplied record through exact index evidence links or
   reasoned exclusions. Explain unresolved contradictions and insufficient
   evidence in limitations. Do not replace withdrawn feedback with invented
   current approval or quietly carry old unaudited Wiki conclusions forward.
6. Check your complete output once for consistent identifiers, acyclic
   hierarchy, useful search descriptions, local links and file/byte bounds.
   Produce a single result. There is no video validation, optimization loop,
   acceptance or publication inside this Agent task.

Keep the result compact enough for one complete `write` call. Reference every
record exactly as required, but avoid repeating the same source ID across
many packages without a concrete need. Keep exclusion reasons brief and
specific. Synthesize useful guidance instead of copying source logs, complete
prompts or long code listings. Input ranges and metadata pages are bounded;
budget context for the final authored result, and disclose any insufficiently
read evidence instead of inventing a lesson or claiming a full inspection.
