# 视频学习任务失败调查（2026-11-19）

本次只读取生产任务库、冻结源码、渲染收据与日志；没有修改生产记录、重新提交任务、调用模型或部署服务。

## 反复失败的任务

- 效果：逆光峰林与云层的纵深和遮挡
- 项目：`68240ff5aecd482289612cde58124dad`
- 初始实验：`f4f33bd8cfeb4b978cddba0cf681ccf1`
- 技术重试：`0136450b26e7486ea8ff728f46ec987d`
- 两次均在 render 阶段失败，创作 Agent 已完成生成。
- 两次源码 SHA-256 相同：`330a60ff88a97581ff61b9db2d35d3a09d8141ec2706b02cc41d7d9c95f0b3b3`。
- 两次实际收据均为 `TimeoutError: page.screenshot: Timeout 10000ms exceeded`，均未写出第一帧。
- 总体渲染时间限为 360 秒，两次约 43 秒退出，因此不是实验总预算耗尽。
- 两次容器均已清理并确认不存在。

## 原因与证据边界

确定的直接故障是首帧截图超时。收据中的 `fonts loaded` 是已完成的日志，不能据此归因于字体下载。

与该故障吻合的主要性能原因是：源码在 1280×720 全屏使用山体 ray marching 和体积云积分，前者最多 144 次迭代，每次计算 12 个山峰距离函数；后者最多 100 次迭代，并在云密度、阴影和边缘中反复计算多层噪声。服务器的 three 渲染被明确配置为 Chromium ANGLE/SwiftShader 软件实现，容器限 2 CPU、1GiB 内存。没有做新的性能重渲染，因此没有声称测得单帧完成耗时或精确计算量。

现有“技术重试”从冻结的失败渲染阶段继续，复用原始源码，不调用创作者修复。它适合临时基础设施失败，但会重复触发同一份高成本源码的失败。

## 顺带发现

“光环交叠、三角网络与球面空间的结构递进”（`501eeb5abc064398a8b5d7a7efdc2097`）前两版已成功渲染，第三版失败，真实收据是 `hyperframes_legacy_seek_missing`。其 classic script 声明了顶层 `const top`，可能与浏览器 `Window.top` 冲突而阻断接口注册；Node 语法检查通过，尚未在浏览器复现该候选原因。不能把这个问题归为相同的 Shader 性能失败。

## 建议修复方向

1. 把 CPU/SwiftShader 环境和实际失败信息提供给创作 Agent，由 Agent 在原目标下修复实现。保留 Three.js 能力，可采用几何网格、有限采样、缓存或分层合成降低成本。
2. 在批量渲染前加入覆盖代表性状态的性能预检，让明显过重的实现尽早获得反馈。
3. 将暂时性渲染失败的技术重试与需要改源码的创作修复分开处理，在本次预算内执行。
4. 页面展示经过分类的实际失败原因；调整截图时间限只能作为有总预算约束的配套措施，不能代替降低每帧成本。
