## 使用

2026-11-19 新增的[按需远程参考合同](remote-reference-learning.md)允许以 `source_type: "video-url"` 注册原站链接，在需要时取得片段或高清局部；以下上传说明继续适用于文件来源。出处备注与可按需访问的远程参考分开识别。是否已经上线，以远程参考验收回执为准。

1. 新建视频学习，上传实际 MP4 或 WebM，最大 24 MiB，源视频不超过 600 秒。原始字节、摘要、尺寸、时长与音轨信息保留。来源网址只作为来源记录，不代替获取媒体。
2. 已明确目标时直接填写片段起止。一次学习 1–60 秒，时长对齐 24 fps，可用整数秒；输出最大 1280×720。说明主要学习画面技法、运动机制或节奏，不默认照搬旁白、背景音乐、水印或画幅。
3. 未确定片段时，明确点击“分析可学习片段”，单独设定预算。新建远程全片分析默认先取8帧概览，上传参考保持24帧；独立 Agent 根据实际画面提出候选，必要时可按原协议补看。概览不等于所有效果均已覆盖。选择候选只填写范围和目标，仍需点击“开始视频学习”才创作，也不会自动为多个候选创建多份作品。改变所选范围时不再冒称原候选选择。
4. 可选择加载或不加载已发布 WikiSkill。开始时冻结确切知识版本、原参考、范围、目标、意见和预算；运行中查看或停止，新意见进入下一次实验。
5. 在详情播放原参考片段和完整生成视频，可按共同片段时间定位、并排播放画面对照，也可分别听取各自音轨。下载 Agent 源码、视频及渲染回执，查看角色实际输入、原始时间和解码 PTS。
6. 普通实验只复现和优化；用户选定认可的实际视频后，可点击“认可并验证换内容”，确认该版本及独立预算。复现和验证分别保存，不自动产生两个首页项目。内部最佳、用户认可验证来源和采用的默认作品分别记录。
7. 可继续优化、从零重做或技术重试。技术重试只传 `{request_id, mode:"retry"}`，不改变原目标、预算、意见或知识绑定；只有源码、没有真实视频的候选不能采用或作为继续优化基线。

新建、继续优化和从零重做默认最多探索 1 轮，时间上限默认 3600 秒（60 分钟）；独立候选分析也默认 60 分钟。可以明确选择更短的预算或其他轮数。技术重试继续沿用原任务冻结的预算，历史任务不会被新默认值改写。

显式换内容使用原 `/projects/{project_id}/experiments`：`mode:"transfer"`、明确 `base_candidate_id`、严格布尔值 `approve_candidate:true`，固定一轮、默认独立3600秒。它不自动采用作品或发布知识；审批身份、输入隔离、幂等及旧自动验证重试规则见[完整说明](user-approved-learning-transfer.md)。

视频渲染的默认执行上限为 3600 秒，并受实验剩余时间约束。作者和评审默认请求 3600 秒，实际执行时间按已准入的平台注册上限及剩余预算裁剪。

列表交互与图片学习库、效果库一致：学习项目与参考分析均以卡片摘要展示，点击后进入各自详情。参考分析的全部候选、难度和完整观察报告放在分析详情内；仅有参考分析时也不显示空库。表单内查看已有分析后可返回继续填写，明确选择候选才带入参考、目标和时间范围，选择本身不开始制作。轮询和手动刷新保留当前查看位置与展开状态。

同一已保存参考的视频分析汇总为一个入口，主页和表单内列表都显示最新创建的分析及总次数。详情的“分析历史”保留各次状态、错误、候选和完整记录；可以切换查看旧分析。默认选择依据 `created_at`，不会用旧成功掩盖新失败或运行状态，也不会因为旧记录更新而改变先后。搜索涵盖历史目标和候选标题。选择历史候选时，仍绑定原 `analysis_id`、`segment_index` 和时间范围。该汇总仅改变展示，不合并或改写冻结记录，不发起复验或学习。

开发者可以持续发起新的有界实验，不受正式影片自动打磨轮数的限制。新作品不自动采用、不自动发布知识。

## 当前观察边界

作者和独立评审直接获得实际帧像素及时间身份。新远程全片分析默认8张初始概览，上传参考默认24张；共享初始读取能力仍兼容最多24帧，既有任务保留原冻结数量。分析输入说明实际采样及覆盖局限，并可沿用有界补看。复现比较分别采集原参考、当前较好作品和本轮实际输出的帧序列。保存请求时间、实际解码时间、整数 PTS、time base 及重复帧映射，重复命中同帧不冒充新增观察。

远程网络读取仍受原128 MiB、请求数和时间预算约束；新默认减少逐帧重复读取，不把超限隐藏为成功，也不改写旧失败。原因及恢复边界见[远程概览与读取预算](remote-reference-learning.md)。

当前模型协议验证范围为 `sampled_frames_only`。采样用于观察画面和关键状态，不能证明未覆盖的过程、连续流畅度、实际听感或音画同步；`continuous_motion_verified` 与 `audio_verified` 保持 false。网页提供完整可播放原视频与生成视频，播放文件存在本身也不等于已经观看。

“学习音效”是本次学习意图。原始音轨仍随媒体保存，Agent 可以按目标安排平台支持的合成音效；当前尚无实际音频输入评审能力，不能据波形、文字或音轨存在补签听审。实际音频观察与按目标加密的连续运动研究仍需后续补齐。

作者可使用当前环境准入的 HTML/SVG、Canvas 2D、Three.js、Manim 与动作工具，产出可编辑动画工程；通过共用 HyperFrames 完整渲染。Manim 学习、内部技法小样与按需分工通过明确的生产者及操作记录执行；具体准入以 `/catalog` 为准。直接视频模型输入、连续运动听审不在这次能力补齐的验证范围。

### Canvas 2D 的绝对时间定位

普通视频学习的 Canvas 2D 宿主在每次绝对时间定位前重置可见且有尺寸的画布。场景的 `seek(seconds)` 要从该时间重绘整张可见画布，包括静态背景、变换、剪裁和绘图样式。只需生成一次的背景、图案等可画到脱离页面或隐藏的缓存画布，再在每次定位时合成到可见画布。场景可以在首次定位时创建画布上下文，并自行指定上下文选项。

动画库的时间轴也应从同一个绝对时间定位。CSS 动画需要保持暂停，并随定位显式设置进度。渲染器拒绝自主运行的 DOM 动画，并对倒退、重复定位、空闲及重新加载采样做像素一致性检查。显式使用 SceneSpace 时，由它的独立合成器按绝对帧重绘输出。

## API 与请求恢复

沿用开发者 OAuth、owner 隔离、同源 Origin 和 CSRF。GET `/catalog` 返回 CSRF、当前账号项目、参考与分析；POST 使用 JSON 和 `X-Animation-Lab-Token`。未提供独立长期机器令牌。

上传 `/references` 的正文为 `{request_id,file_name,mime_type,content_base64,source_url?}`。实际媒体检查在创作前进行。明确片段创建 `/projects` 使用：

```json
{
  "request_id": "38ec2b0b-6979-4fe6-8abf-c76b9779bb24",
  "title": "触发与群体响应",
  "goal": "学习局部触发如何通过错峰动作传播并收束。",
  "reference_ids": ["实际上传返回的编号"],
  "start_seconds": 21,
  "end_seconds": 28,
  "learn_audio": true,
  "use_wikiskill": false,
  "max_rounds": 1,
  "max_seconds": 3600
}
```

独立分析 POST `/references/{rid}/analyses`：`{request_id,goal?,max_seconds?}`，预算 60–3600 秒，省略时默认 3600 秒；GET `/references/{rid}/analyses/{aid}` 查询，POST 同路径 `/stop`，正文 `{}`。分析不创建项目、不自动执行候选；选择候选时可附 `analysis_id` 和 `segment_index`，后台验证同一参考、分析已完成与确切范围。

其余项目接口与图片库同语义：GET 详情及 `/experiments/{eid}/input`，POST `/experiments`、`/stop`、`/adopt`，GET `/artifacts/{aid}`。所有 owner 由鉴权链路提供，不接受 JSON 中指定别人的身份。

网页用 IndexedDB 保存原提交，包括视频上传和后续操作。结果未知时按原键恢复，刷新只读查询；只有明确点击“重送原请求”才重送同一正文，不自动换编号再次消耗。分析与制作的请求身份、预算和停止证据分别保留。

## 选择能力与按需探索

新建、继续优化和从零重做与图片库共用 `capability_selection`、`allow_probes`、`allow_collaboration`。例如在原 `/projects` 正文中添加：

```json
{
  "capability_selection": {
    "creation": ["canvas", "three"],
    "motion": ["gsap", "native-js"]
  },
  "allow_probes": true,
  "allow_collaboration": false
}
```

画面创作和动作编排是不同职责，多选允许作者从所选能力中按目标选择或组合，留空交给 Agent 在当前准入范围内决定。网页从 `/catalog` 的 `capabilities` 停用未准入选项；仅选 Manim 时自动清空并停用浏览器动作编排，使用 Manim 自身动画接口。Manim 先真实生成资源，再由完整影片源码通过绝对时钟消费，不以普通绘图假冒生产者输出。

上例的动作工具仍须以实际 `/catalog` 返回为准。当前学习渲染器尚未准入 Anime.js，需求创作库中已经可用并不等于两学习库也可直接选用；不可静默替换明确指定的能力。

视频学习可输出最长 60 秒的完整片段；本轮 Manim 资源自身则限制为 24 fps、最多 60 帧、最多 128 MiB 解码像素，并在更长片段中按明确位置消费。这两个时长范围不同。资源从局部第 0 帧开始，整体放置使用全局半开区间，区间外不得遗留图像；实际 Python、产物摘要、使用位置和渲染消费分别留证。资源成功不等于完整运动或艺术质量已认可。

开关默认允许 Agent 在首次复现确有必要时安排最多两个真实技法小样、两至三个部件，关闭可禁止相应工作。小样经过创作、完整渲染和独立帧评审；部件保留源码、接口和真实操作身份，再整合完整影片。所有任务共享本次预算与截止时间，按依赖顺序执行（`max_parallel=1`），不会递归扩张任务或自动增加探索轮次。当前采用 Manim 资源的方案不与内部小样/分工子任务组合。

`experiments[].learning_progress` 显示真实阶段；`internal_attempts` 仅在实验历史的证据区显示可播放小样、源码和评审，不成为独立效果卡、默认作品或换内容验证。采样帧评审仍不能补签连续运动和音频质量。技术 `retry` 保留冻结选择和成功内部产物，不接受新的能力与开关字段。
