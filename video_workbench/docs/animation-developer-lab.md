## 使用方式

在 `panghu_agent` 仓库根目录启动独立入口：

```sh
python -m video_workbench.animation_lab \
  --data-dir video_workbench/rendered/feedback-20261106/animation-lab/data \
  --assets-dir video_workbench/rendered/feedback-20261106/animation-lab/assets \
  --port 8766
```

默认本地模式只监听本机 `127.0.0.1`。使用浏览器打开 `http://127.0.0.1:8766/`。`--data-dir` 与 `--assets-dir` 必须显式提供，端口默认 8766。这是独立开发工具，本地启动不需要登录业务工作台，也不提交 Agent、TTS 或生产渲染任务。实验数据不进入业务项目数据库；最初本地交付阶段没有部署到服务器或公开域名。

后续用户已单独授权服务器部署，独立服务器模式通过现有Casdoor登录限制开发者身份。固定入口、部署进度、存储迁移和实际验收见[服务器部署说明](animation-lab-server.md)；默认本地命令不会自动启用远程访问。

`--assets-dir` 指定现有可信渲染资源目录，包含 `gsap.min.js` 和 `NotoSansCJK-Regular.ttc`。工具在启动时读取并冻结实际资源字节，记录摘要，检查 GSAP 版本和字体文件头；资源缺失或不符合要求时直接启动失败，不用联网 CDN 或其他字体替代。首批样例使用生产编译器生成的 HTML/SVG/GSAP 画面，浏览器预览不等于 MP4 编码结果。

## 首批样例与范围

| 模块 | 对比内容 | 检查重点 |
| --- | --- | --- |
| 框图与信息图 | 相同输入在明确的历史基线和当前编译器下的画面 | 布局、文字、连线、初始显隐及动作顺序 |
| 二维过程 | 同一个对象的传递、失败返回、重试和状态变化 | 路径、停靠、状态反馈、节奏及归零 |
| 跨镜衔接 | 固定两镜的独立播放与连续承接 | 对象身份、状态延续、位置衔接及转场边界 |
| Canvas 2D | 真实 Canvas 请求积压与队列消退 | 请求数量、排队与分发、阶段聚焦、反向状态恢复 |
| Three.js | 真实 WebGL 分层系统展开与聚焦 | 空间层级、相机变化、对象保留和重组 |
| 讲解效果（框图/过程分类） | 条件分支、并行等待、结构展开、重点迁移、数据比较、代码执行、局部替换和SVG形变 | 对象、条件、数据和动作是否对应，绝对时间恢复是否完整 |

两类新引擎各提供一个18秒静音案例和两个比较版本。本地 Three.js 的安装、资源身份、失败诊断及真实采样结果见 [Canvas 2D 与 Three.js 开发者小样](animation-canvas-three-lab.md)。

随后新增八类各18秒的固定讲解效果，当前共十五例；每类两个同语义、同音频时钟的版本。它们复用原分类与标注，不改变旧七例身份和历史；同属框图分类也不会获得旧配方的 `flow`/`focus` 编辑能力。用途、编译合同和实际验证进度见 [八类讲解动画效果](animation-explanatory-effects.md)。

历史版本仅用于开发对比，不能因此扩展生产准入。两个版本的时长可能不同，尤其连续转场会增加时长；对比页保留各自时长，较短侧到达末帧后停留。首批是无旁白技术样例，静音输入只用作固定时间夹具，不支持评价语音自然度或真实字词同步。

## 标注一次效果

1. 选择模块和样例，查看基线 A、候选 B 及各自版本说明。
2. 同步播放或拖动，必要时逐帧查看动作前、中、后或跨镜边界。
3. 选择具体版本，填写时间点或区间；需要指出局部问题时，在画面上框选区域。
4. 记录问题类别、严重程度和具体意见，也可记录 A/B 偏好或本样例已审阅。
5. 保存后检查历史记录。刷新或重启工具后，标注仍应存在。

问题类别覆盖布局、文字、连线、动作、节奏、衔接、表达和其他；A/B 偏好可选择基线、候选、相当或两者都不合适。人工效果评价可以记录“效果可接受”或“还需改进”。这些评价只属于当前开发样例，不改变生产视频的旁白时序核准或正式采用；机器检查通过、开发者偏好和正式业务采用分别记录。

标注绑定完整的样例身份、版本身份、编译产物和运行资源摘要。输入或实现变化后，新实验拥有新身份，旧意见继续保留，不能静默移到另一份画面。区域使用相对画面的归一化坐标，便于在不同显示尺寸下定位；时间保存为秒并附带固定帧率上下文。

同一样例名可以积累多个历史身份。旧身份记录会标明“来自历史样例版本”，当前画面的跳转与框选定位禁用，原始意见仍可导出。误点时可撤回标注；撤回是新的事件，原记录与撤回原因继续保存。

## 如何让后续迭代利用标注

导出的 JSONL 包含冻结样例输入、基线/候选版本、编译产物及原始标注。HTML、JSON、WAV 等样例产物以 Base64 保存并附内容摘要；GSAP、字体和预览适配器记录摘要，Three.js 案例另绑定所需模块摘要。依赖与字体二进制继续保存在显式资源目录中，不内嵌到每条导出。复现时需要保留并匹配这些资源，导出不等于封装了完整浏览器环境。

每条标注导出时提供 `effective` 和 `superseded`。相同案例身份、版本范围和类别下，偏好/人工评价以最新未撤回记录为当前有效意见；此前意见保留为被替代的历史。撤回最新意见后，上一条未撤回意见重新有效。问题标注保持独立，撤回前均有效，不因新增一条意见而自动判定旧问题已解决。

后续开发可以据此复现问题、汇总偏好、选择修改方向，并将已确认的问题转成该模块的回归案例。例如“连线标签挡住请求对象”应转成对应布局与动作时间窗的检查，修改后重新提供同输入对比。读取评测数据时应优先使用有效记录，保留历史用于了解意见变化。

每个模块独立维护代表性样例和效果检查。浏览器检查关注实际画面；确定性编译检查负责版本及冻结输入；只有影响共享时间轴或输入合同的修改才扩大相关回归。发布前仍应完成与变更有关的集成检查。

这里的“学习”指持久保存、读取和使用明确的评测与偏好数据。工具不自动训练模型、不把单条意见当作通用规则，也不自动更改生产模板。将来接入 Agent 或其他训练过程时，需要另行设计数据筛选和回归验收。

服务器工作台已增加按模块的有效意见汇总、增量任务和开发进展交接；使用方式与独立 GitHub 开发执行器见 [动画反馈到 GitHub 的开发迭代](animation-feedback-iteration.md)。任务导出、外部执行、候选样例验收与生产采用分别记录。

## 本地接口

| 接口 | 内容 |
| --- | --- |
| `GET /api/catalog` | 当前模块、样例、比较版本和运行资源身份 |
| `GET /api/annotations?case_id=...` | 指定样例的全部标注，包括旧身份与撤回历史 |
| `POST /api/annotations` | 保存绑定当前冻结身份的新记录；过期身份返回 409 |
| `POST /api/annotations/{id}/retract` | 追加撤回原因，保留原标注 |
| `GET /api/export?format=jsonl` | 导出所有已保存快照和标注，附当前有效性 |

写请求由同源页面携带工具令牌。数据目录不会作为静态目录开放；工具只提供固定 UI、可信编译产物和指定资源。
