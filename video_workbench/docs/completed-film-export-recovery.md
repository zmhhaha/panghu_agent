# 已完成场景的整片导出恢复

正式 production-runs 接口支持显式指定
`reuse_completed_prefix_from_run_id`。失败任务的场景已全部完成、唯一整片导出已失败并有真实停止证明时，可以创建一个新的标准任务，复用原场景版本，只执行一次新的整片导出。新任务的预算为零个新作者任务、零个新录音、一个整片导出。

这条路径校验原任务、全部模块操作、版本、输入、源码、资产、前驱、转场以及原导出与快照。旧任务和旧导出保持终态。新任务仅继承模块条目、模块意图及原目标命名空间，使用自己的导出意图与快照身份。完整来源会在接收任务、组装和真正提交执行前重新核对。原记录发生变化会被拒绝。

同一执行版本的恢复保留原来的精确配置比较。未完成前缀的恢复仍要求原任务尚未创建导出。GET/list 和原幂等键的重放不创建恢复工作；调用方使用新的任务请求键，并显式选择原来源。

## 执行版本更新

为修复 Canvas2D 截图阻塞而改变可信浏览器 host 后，镜像、host 和执行准入身份都会变化。原模块仍记录创作时的执行身份 A，新导出必须记录实际执行身份 B。

这一特例由服务端文件
`VIDEO_FILM_SOURCE_RUNTIME_ADMISSION_FILE` 配置。缺省时保持严格的同版本行为。请求正文和 Agent 输出不能提供或授权策略。

策略只允许一部明确指定的、静音 300 秒、十二个场景已全部完成的影片。它固定来源的 owner/project/run、原导出和快照、完整配置 A、按顺序排列的十二个原包摘要，以及独立准入的目标 B。引擎、模块 profile/bundle、资产、许可、库和能力供给必须一致；六个可信 host 中仅允许经过验证的浏览器 host 变化。完整数据格式和校验由
[film_source_runtime_admission.py](../film_source_runtime_admission.py) 定义。

目标 B 先独立完成真实技术准入，再生成策略 P。新当前配置 C 包含 P，之后才计算 C 的摘要；P 不包含 C 的摘要。服务端生成的来源回执绑定 A、P、新任务与 C。原模块与模块操作仍使用 A，新的整片操作与所有下游快照、执行和媒体回执使用 B。

如果已有 Manim consumer context，原 producer、resource image 和 helper 摘要保持一致。只有经独立验证的 consumer admission 与其完整 formal release 可以精确绑定到 B；这不允许新增资源工作。相关原、新准入证据都进入策略。

策略文件必须是只读普通文件。使用 Kubernetes ConfigMap 时，以单文件 `subPath` 挂载；整个投影目录内的符号链接会被严格加载器拒绝。每次准入会重新比较已加载策略与文件内容。新配置中的策略、来源回执和十三个原停止操作摘要都会再次校验。跨版本恢复只能选择策略指定的原 A 任务，不通过衍生任务建立兼容链。

## 验证范围

本地回归覆盖真实 HTTP/workflow、十二段完整复用、无新作者或音频、一次新导出、旧记录逐字节保留，以及排队后来源文档、SQL 身份、策略或回执变化时拒绝提交。媒体测试使用合成夹具；实际目标镜像的 ARM/Kubernetes 执行、清理、完整音视频解码和最终影片运动/画质检查仍需单独保留证据。

恢复沿用任务冻结的 WikiSkill 发布版本，不创建知识发布。截图完成、库调用成功和身份校验通过均不表示艺术质量已被接受。
