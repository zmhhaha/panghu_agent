# 2026-11-04 视频用户反馈修复

反馈来源：[Issue #1](https://github.com/zmhhaha/panghu-service-feedback/issues/1)、[DSH 八镜头实测](https://github.com/zmhhaha/panghu-service-feedback/blob/main/services/video-service/retest-2026-11-04.md)。该次用户已取得174秒完整有声草稿，但首轮只有3/8镜头草稿成功，返工后完成。此前两镜19秒技术验收不能替代这些复杂内容和交错编辑场景。

## 实现

- **VID-011**：空镜头或空步骤禁用核对范围，显示本地输入说明；校验错误不再被报为断网，成功操作清理旧全局提示。未启动的范围项显示“待制作（尚未启动）”。
- **VID-002**：编辑草稿记录完整原始可编辑字段。全项目版本变化时，服务端在同一写事务中比较当前镜头与原始字段；无关任务更新可以安全保存，真实同镜修改继续拒绝并保留草稿。旧客户端不带原始字段仍使用严格版本门禁，未来版本、越权和付费任务门禁不放宽。
- **VID-005/006**：历史列表只读补齐冻结来源的镜头名、图解/配音版本、规格和时间；批次播放按render ID解析真实记录，不以当前项目版本补旧记录。只在相关内容、音频、时序锚点、字幕或正式采用组合改变时提示变化。当前草稿与正式视频均固定1280×720、24fps，界面明确说明；不将文本中的1080p要求当作已实现规格。动态拆分输入明确动态、无附加字幕的当前制作模式。
- **VID-004**：执行器在原journal JSON内保留实际阶段、当前镜头、完成数和脱敏问题编号。工作台按相同owner/operation/snapshot绑定保存阶段回调；终态不接受迟到回调。已知渲染、观察、音画合成、文字溢出、高亮、存储、超时等错误分别说明；未知失败不猜测根因。保留同ID恢复、取消和资源清理，诊断不返回stderr、路径、凭证或owner。
- **VID-012**：新输入使用compiler5，正交连线避开无关卡片及标签，关系文字换行并有独立底板，也避让移动token经过区域。实际SVG ink/plate及中间帧几何仍需严格校验。重复高亮使用独立outline脉冲，按时间线核对显隐及脉冲，支持同窗显现和高亮，仍拒绝完全不可见的强调。compiler1～4及历史snapshot保持原输出规则。
- 整片草稿及正式制作提供可关闭的最后画面至少停留4秒选项。通过尾部静音停留延长画面，不改原音频字节、动画动作时间或人工核对状态；旧请求默认0，旧幂等键保持兼容。尾卡完整URL与资料核对日期需要显式来源输入，本轮不虚构这些事实。

## 原始失败证据

只读核对原八镜头项目 `9d492352-4e73-4c43-b050-cf6a76c0b93b` revision59：第3镜及其直接重试、第7镜均为 `motion_expected_highlight_missing`；第4、8镜为 `motion_invisible_highlight`；第5镜为 `motion_text_overflow`。业务与执行器错误一致。简化后成功不等于原失败是OOM或内容复杂度。

原第3、7镜的同一对象有重复高亮；第4、8镜高亮与显现同起点。旧校验要求每次高亮前后颜色不同且之前已完全可见，与永久绿色和同窗显现冲突。该结论来自冻结计划和时间线；旧实际观察产物已按清理策略移除，opacity摘要明确记为 `modelled_not_observed`，不能当作真实Chrome观测。原失败记录未改。
