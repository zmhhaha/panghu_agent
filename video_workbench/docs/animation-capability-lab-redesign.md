# 动画能力实验重新设计

2026-11-08 至 2026-11-09。状态：首轮四个真实作品、独立技术复核、媒体比较与反馈验收已完成并发布；共享创作 profile 随后已通过增量准入，实验室和正式调用方均验证可用。新增三项语义能力的首作、技术检查、Lab发布和浏览器验收亦已完成，效果保持待评价，详见“当前扩展”。开发分支为 `codex/video-capability-experiment-redesign`，首轮 OpenSpec 变更为 `redesign-video-animation-capability-experiments`，本轮为 `add-semantic-animation-capability-experiments`。代码测试通过与真实实验完成分别记录，不能互相替代。本文保留首轮执行与发布的历史事实；后续正式接入和实际发布身份见[动画实验成果进入正式制作](animation-capability-production.md)。

## 要解决的问题

实验的单位改为“一个需要改善的动画能力问题”。不再按行业、引擎或模块凑样例数量，也不要求为每个问题先写业务故事。圆、方块、A/B/C、简单数值和符号即可。

本轮核对发现，当前39个公开样例由固定 Python/JavaScript 配方生成，打开或切换样例不会调用 LLM。多数 A/B 只改描边、透明度或高亮；场景数据不同不能据此认定表达策略不同。保存标注不会自动改提示词或训练模型。已有技术检查证明了有限输入下能正确渲染，没有证明模型创作能力得到提升。

重新设计开始时，生产链路只接收通用 Agent 输出的受限 motion/process JSON 计划，由确定性编译器负责布局和动作，再交 Hyperframes 渲染。这些计划无法表达任意路径形变、Canvas 粒子、Three.js 相机和材质。后续已增加 HTML/SVG 源码候选的独立准入与隔离渲染路径，旧计划路径继续保留；Canvas/Three 自由生成仍未进入正式准入。优化提示词能改善已有表达空间内的选择；增加表达空间仍需要相应契约、实现与验证。

## 新的实验方式

同一个工作台支持以下两类实验，明确显示产物从哪里来。

| 类型 | 输入与实际执行 | 反馈能改善什么 |
| --- | --- | --- |
| 组件实验 | 最小几何输入，由指定版本的代码或算法运行 | 路径、避让、形变、镜头、时钟与渲染组件 |
| 模型创作实验 | 最小能力目标，通过通用 Agent 真实生成计划或场景代码，再隔离渲染 | 提示词、表达策略选择、编排与生成能力 |

两类实验都允许先探索，再比较。探索阶段可以只有一个作品，没有强行制造的“基础版/优化版”。不同方案可以采用不同的路径、空间关系或镜头，不预先规定一个固定配方。选出值得验证的方向后，再进行受控比较。

比较时冻结目标、对象、初末状态、时长、资产、运行环境和模型配置。每轮只选择一个改动来源，例如提示词版本或布局组件版本。这里的“一个改动来源”不是要求模型输出只能改一个动作；模型仍可以在相同目标下重新组织整段表达。若同时改提示词、模型和渲染代码，只能记为组合探索，不能归因给提示词。

探索记录回答“有什么不同做法”；比较记录回答“这次改动是否更好”。不把候选 B 命名为“优化成功”，也不提前指定胜者。

## 能力问题目录

下面是可独立优化的问题标签，不是需要一次做完的样例配额，也不与某个固定模板绑定。每次依据真实问题选一项开展实验。

| 问题 | 最小输入 | 有实质差异的研究方向 |
| --- | --- | --- |
| 运动与节奏 | 一个方块，几个停靠点 | 加减速、停顿、错峰、运动重叠怎样影响跟随感 |
| 布局与避让 | 若干 A–L 方块及短标签 | 固定布局、局部重排、约束布局的稳定性和可读性 |
| 连线与显现 | 几个节点、障碍和依赖关系 | 端点跟随、绕障、对象就绪后再生长；避免提前露线 |
| 移动中的身份追踪 | A/B/C 交换位置 | 路径分层、错峰、空间分离怎样帮助追踪同一对象 |
| 连续形变 | 圆、方和凹轮廓 | 对应点、路径重采样、轮廓演化；淡入淡出不算轮廓形变 |
| 跨镜承接 | 同一对象跨两个视图 | 锚点、速度、尺度和上下文怎样连续，而非每镜重新出现 |
| 数据联动 | 两组匿名数值和曲线 | 公共游标、数值对应、坐标稳定与视图间的关系 |
| 符号变换 | A+B=C 等简单表达式 | 保留符号身份、对应移动与分步变化，而非整行替换 |
| 聚焦与上下文 | 一个面板及局部目标 | 镜头推近、局部放大窗、重排等不同注意力策略 |
| 点群与轨迹 | 固定种子的点群 | 聚散、流动、轨迹衰减、密度与层次，不绑定排队故事 |
| 波形与场 | 简单波形或数学向量场 | 采样、叠加、重建、缩放时的连续性和可辨性 |
| 三维装配 | 块、杆和带孔板 | 依赖顺序、避碰路径、展开与还原 |
| 三维剖切 | 简单内外结构及切平面 | 裁剪、真实截面与封口、内部结构呈现 |
| 三维镜头与遮挡 | 几个几何体和标签 | 自动取景、避挡、投影标签、平滑镜头路径 |

同一种策略的不同对象数量、画幅、标签长度、速度和种子，放在该实验的参数回归中；不再占据主目录的新作品位置。领域内容只在确实需要验证知识正确性或业务接入时加入。

## 一张实验卡需要的信息

1. **问题和目标**：要改善什么，观看者需要看懂或跟随什么。
2. **最小输入与约束**：对象、初末状态、时钟、画幅、资产及运行预算。
3. **允许探索的空间**：可以改变的空间、运动、镜头与组织方式，以及本题必须遵守的语义。
4. **来源与改动**：组件实验或真实模型生成；这次修改的是提示词、组件还是其他因素。
5. **实际作品与证据**：原始计划/代码、可播放媒体、真实执行回执和版本。
6. **检查与评价**：技术失败、表达偏好、具体时间/区域意见分别记录。
7. **结论与下一步**：保留、继续研究或放弃；对应哪条通用规则、提示词或组件修改。

没有执行的卡片显示“实验定义”，不显示可播放作品或通过状态。手写作品明确标为手写，不以模型图标或生成文案混淆来源。

## 如何真正用反馈改进提示词

模型创作采用“冻结目标 → 真实生成 → 隔离渲染 → 评价 → 修改提示词 → 同目标重测 → 未见输入复测”的闭环。

- 每次保存完整提示词及摘要、profile/工具包版本、模型请求配置与服务实际返回的模型信息、Agent 任务和尝试回执、原始产物、组件及运行资源摘要。服务没有返回的信息标为未知，不能从请求值推断实际值。
- 使用同一模型配置、资产和组件比较提示词。请求 seed 只有服务明确支持时才记录为生效；不宣称模型输出可逐字确定性重现。归档产物的渲染才要求可复现和可反向定位。
- 新创作 profile 目前没有“旧提示词”。首先建立真实运行的 v1 参考，再从反馈形成 v2；手写基线与模型作品可以比较效果，但不能当作提示词 v1/v2 实验。
- 一次偏好只说明该次比较。另选未用于修改提示词的参数组合或目标复测，记录失败和全部尝试；若证据不足，结论保持“待复测”，不挑最好的一条冒充稳定改进。
- 留出输入在开始调优前划分，不能进入修订提示词的示例或反馈包；被查看或用于调优后转为公开回归，再划分新的留出输入。
- 反馈落实到可执行规则。例如“运动中容易丢失 A”可推动路径分离或错峰的选型规则；若生成计划根本没有相应表达字段，则记录为契约/组件缺口，不能继续堆提示词。

现有 `workspace-task.v1` 反馈执行器继续负责提出源码修改及开发分支/草稿 PR。它与“目标 → 生成动画作品”的调用分开；保存标注、打开预览和登记任务都不代表这两个执行过程已发生。

## 什么算新的表达策略

按信息与运动的组织机制判断：对象如何对应、如何移动和变形、动作如何排序、视角如何解释关系、焦点如何转移。颜色、业务名词、描边、阴影、同一路径的少量参数改变，不单独算新的表达能力。

不依赖模型自报的 `strategy` 名称证明创新。对产物做对象/路径/时序/相机变化检查，必要时查看实际视频；模板和产物摘要可辅助发现完全重复，但无法可靠证明语义上的新颖。不同代码也可能产生相同画面。重复作品记入同一策略的尝试和回归，不继续刷样例数量；外观调整仍可作为有明确目标的可读性实验。

技术检查关注身份与初末状态、碰撞/遮挡/越界、连线和几何正确性、动作前泄露、时间连续性、反向归零及资源消耗。各探针在比较前冻结适用阈值，不用同一个指标处罚所有表现手法。人的评价关注容易跟随、视觉焦点、节奏、空间理解和美观；允许“两者都不好”及不同评价维度各有优劣。视觉模型只能辅助，不取代真实几何检查或开发者判断。

旧配方专用观察器不能直接认证自由生成作品。通用运行检查由受信宿主采集；目标检查从预先冻结的输入独立推导，并与真实画面或几何对应。生成代码自己上报“对象存在、目标到达、检查通过”，只算声明，不是独立证据。

## 真实生成接在哪里

已有框图计划的提示词实验复用 `video.motion-plan.v1` 的真实 Agent 和编译链路，明确其动作/布局限制。

需要创造 SVG/Canvas/Three.js 动画代码时，使用 Lab 专用 profile `video.animation-experiment.v1`。已实现本地契约、独立工具包和注册代码；服务运行登记及真实验收状态见本文末尾。复用已有通用 Agent 服务、任务上传、限额、取消和停止证明、产物回收机制，不为每种能力另建服务。输入是冻结能力目标和本地可用资源契约，输出包含 `scene.html`、可选本地脚本及 manifest 的有界场景包。manifest 绑定输入、工具包、引擎、时间接口及产物摘要，模型描述的“效果通过”不作为验证结果。

场景从绝对时间求状态，使用受信宿主提供的 seek 接口；运行时禁止拉取 CDN、安装依赖或访问业务数据。停止写入和包校验后才进入隔离渲染 Job，设置时长、文件、CPU/内存及输出限制。真实模型代码的执行边界需要单独实现与验证，不能因已有固定样例能播放就视为已经具备。

现工作台的可信 iframe 同时允许脚本和同源，用来播放固定编译器产物；不能直接用来运行模型代码。新 profile 首版在隔离环境渲染，只向工作台交付视频、逐帧图片和验证报告。确需交互代码预览时再设计无凭据隔离 origin 或 opaque-origin 沙箱及消息协议；不能将未审脚本送入当前已登录的同源页面。

生产接入作为独立变更 `connect-animation-capabilities-to-video-production` 实施：把有证据的策略发布为不可变规则包，实验与正式新候选冻结同一包；HTML/SVG 源码在隔离渲染器执行，经预览和明确采用后进入普通整片制作。它不把任意实验源码直接送入旧 `scene_compiler`，也不因一条作品更好就自动更新生产默认规则。Canvas/Three 的正式生成与编码仍需分别完成引擎准入。

## 当前扩展：三项语义能力实验

2026-11-09：新增能力位于开发者工作台的“能力实验”，与原“换位时跟住 A”并列；“组件与参数回归”的固定样例继续单独使用。对应 OpenSpec 为 `add-semantic-animation-capability-experiments`。能力目录、开发输入和未参与调优输入均按版本冻结，旧身份追踪定义和输入保持原字节。新能力首先不绑定旧 `explanatory-motion-v1` 策略包；实际作品、反馈、复测与策略发布分别记录。

| 能力 ID | 表达问题 | 独立检查与人工观看范围 |
| --- | --- | --- |
| `cohort-statistics` | 对象筛选、重组和统计数值怎样共同解释分母与权重 | 独立核对身份、实际可见数值；稳定区间核对保留/排除/未知状态、人数、已知数、均值及加权均值，`1<t<4` 的筛选过渡期不核对筛选状态与聚合值；分组、权重解释、移动策略与可读性需看片 |
| `parameter-geometry` | 同一矩阵怎样联动点集、基向量、单位面积和公式 | 逐帧核对真实 SVG 点像、线端点、单位多边形及实际显示的行列式/面积倍率；附加公式、坐标轴、标签距离及整体解释需看片 |
| `event-delay` | 下单、在途、到货和消耗的多轨时间怎样解释库存变化 | 独立核对实际可见事件状态、库存、在途量和累计量，到货前不入库、同刻事件不丢失；库存曲线、事件路径与焦点组织需看片 |

三题都使用通用 Agent 自由创作 HTML/SVG，8 秒、1280×720、24 fps。输入中的 `semantic.observation_contract` 规定可测的主要可见节点，不限定整体卡片构图；受信宿主在隔离执行世界测量真实文字和几何，Python 根据原始输入独立复算。技术结果的范围为 `visible_semantic_text_and_svg_geometry_v1`，不宣称完整遮挡、可读性、所有附加公式或曲线均已自动认证。

命令行用 `python -m video_workbench.animation_experiment_runner init --directory <新目录> --experiment cohort-statistics` 创建冻结计划，其他两题替换能力 ID。打开页面不提交任务；执行器继续在服务器独立使用受保护的调用凭据，网页仅显示产物和证据。新能力先各一个开发探索作品；未参与调优输入预先冻结，未执行的修订比较和留出复测保持未运行，不以首个作品证明稳定改进。
