# 图片与视频学习的按需远程参考

2026-11-19 的新增目标是保存原站链接，需要观察时再访问原站，而不是先下载、上传并长期保存完整参考视频。OpenSpec 为项目 `ec663f5a-53d3-4a0e-9037-933eb788d183` 的 `add-on-demand-remote-reference-learning`。2026-11-20 已上线，实际取源与发布边界见[验证记录](remote-reference-validation-20261119.md)。

## 来源与结构化接口

两库复用同一远程参考读取器，均支持视频链接、上传和已保存参考。旧上传正文中的 `source_url` 仍是出处备注；显式 `source_type: "video-url"` 才表示需要时访问的远程参考。POST `/references` 返回来源编号，之后沿用各库的创建或分析接口。

视频参考：

```json
{"request_id":"request-1","source_type":"video-url","source_url":"https://www.bilibili.com/video/BV1BxWu6SESe/"}
```

图片从视频取帧：

```json
{
  "request_id":"request-2",
  "source_type":"video-url",
  "source_url":"https://www.bilibili.com/video/BV1BxWu6SESe/",
  "timestamp_seconds":21.5,
  "crop":{"x":0.2,"y":0.1,"width":0.5,"height":0.6}
}
```

裁剪采用原始画面的归一化坐标。注册可解析必要的来源、时长和可用画质，直接媒体可探测有限容器数据，但这不表示已经观察画面。目录与页面刷新不触发模型或创作，也不读取所有参考帧。原站网页链接不作为媒体播放 URL。

首批适配 B 站公开可访问播放流和公开 HTTPS 单文件。源站或账号允许的实际画质会记录；链接不天然比上传清晰。访问或画质受限、来源改变时明确报告，不暗中换源。凭据仅由宿主配置，不进入用户表单、Agent 任务或公开响应。

宿主默认使用系统 DNS。若代理 DNS 返回 `198.18.0.0/15` 等虚拟地址，读取器会拒绝，而不把这些地址放行。该环境可显式配置 `--remote-reference-dns alidns`：通过固定公网引导地址和 TLS 校验解析真实公网地址，随后仍检查每次连接及重定向的目标；不修改系统 DNS。HLS、直播、加密媒体和分段 durl 暂不准入。

部署清单的 `remote_reference_dns` 默认关闭；配置后仅给可信执行器的参考读取增加公网 TCP 443 出口，排除私网、链路本地、Fake-IP 等地址，保留现有 DNS 和内部 Agent 规则。场景渲染与 Agent 工作容器不因此获得网络。既有集群通过带 resourceVersion 的补丁增加同一条规则，不覆盖其它网络策略。

## 按需观察与角色接力

图片学习开始时取得所选帧，仍由 Agent 创作绘制源码、真实渲染 PNG 和静态对照；视频学习按片段或独立全片分析取得概览。2026-11-25 的取帧修复将新建远程全片分析的默认概览改为 8 帧，上传参考继续默认 24 帧。共享宿主仍兼容最多 24 张初始帧，既有分析继续使用原冻结数量；角色每次补看仍限 8 帧，两种上限分别约束不同阶段。概览采用较小画面，细节可请求最大 1920×1080、2 MiB 的帧或局部，不再一律缩成 640×480。

分析输入明确本次初始采样数量、源时间范围和覆盖局限。少量概览不能证明所有章节或效果都已观察；需要具体细节或遗漏时，沿用下述按需补看协议，仍受原截止时间、来源及供图预算约束。一个分析也不会自动为所有候选新建复现作品。

角色需要补看时，通过现有 `write` 工具交付 `observation_request` 并停止。宿主确认停止后，在许可来源和时间范围内取得真实像素，再通过新的角色操作接续同一轮；不增加优化轮次或总预算。每次最多八帧，最多四次补看，受原截止时间约束。

```json
"observation_request": {
  "reference_id":"本任务许可的参考编号",
  "times":[21.5,22.25],
  "quality":"detail",
  "crop":{"x":0.2,"y":0.1,"width":0.5,"height":0.6},
  "reason":"查看墨带边缘、飞白和山体转折"
}
```

该结果保留正常 schema、input_sha256、mode 和 evidence_scope；`source/review/transfer_task/method` 均为 null。请求不是同步返回的图像，不得与成品源码或完成评审混合。角色供图仍遵守已准入的数量和字节预算；历史证据可保存，但只有本次实际供给并成功传输的像素能作为该次角色观察依据。

## 全片概览与读取预算

一次远程观察的网络读取预算仍为 128 MiB，累计的是来源解析、容器探测及解码的原始网络字节，不是最后供给模型的 JPEG 大小。当前逐帧解码可能重复读取相同容器范围；固定24帧的全片概览曾因此在模型提交前触发 `remote_reference_byte_limit`。新远程分析先取8帧，减少这条默认路径的不必要读取；它不保证任意来源都能在原预算内读完。

读取超限、来源变化或时间无法核验仍明确失败，不提高预算、不自动换编号重跑模型或创作。旧分析失败记录与已冻结的24帧输入不原地改写，后续明确选段学习的成功也不补签全片观察成功。源码、部署和真实来源复验分别记录，完整连续运动及听审仍按实际证据判断。

## 身份、缓存与复验

来源元数据使用 `source_snapshot_sha256`，`source_identity_scope` 为 `provider_metadata`。它不是完整媒体 hash，不能证明未观察部分未变；真正像素证据使用图像 SHA-256，记录请求时间、解码 PTS/time base、源尺寸、供图尺寸与裁剪。

宿主按需传输必要容器范围，以内存和任务临时目录处理，完成、失败和超时均清理，不把完整远程视频写入长期 blob。实验仅保留实际使用的有限画面证据和来源定位；生成作品、绘制源码、渲染回执与方法正常保存。

技术 `retry` 复用已经冻结的实际观察，不暗中换成源站后来变化的画面；新实验可重新读取并保留来源变化记录。观察不自动采用或发布 WikiSkill，静态、采样运动、整段运动和听审分别验证；发布方法必须自包含，外部视频不是技能的运行依赖。
