# 统一画面采样

本轮只抽取画面采样与证据能力。图片学习、视频学习、效果实验、能力实验和正式制作保留各自原有的目标、评价指引、结果结构、分数、问题与停止含义。正式影片原有音频、音画同步和连续视听相关检查继续由原流程执行；图片样帧不能证明这些项目通过。暂不启用新的分类评价标准。

后续顺序是：采样验收，再将各场景现有评价内容原样整理成 Skill，之后用固定证据和预期样例优化这些 Skill。采样模块不加载或修改评价方法，当前没有迁移 `panghu_skills`，也没有重评历史作品。

新学习/效果请求显式选择新版标准会在创建前拒绝；正式制作的新 source-import 分类评审及续验 POST 同样暂停。历史记录的 GET、原件和冻结解释保留。独立的外部离线成片导入工具不属于本轮正式服务入口，没有新增离线导入操作。

## 服务和读取边界

private executor 的 `VisualSamplingService` 是共用持久化实现；`create_server` 将同一个实例交给各实验室服务、渲染器、SceneSpace 队列及私有传输。正式 Workbench 与离线能力实验通过原固定 origin、独立认证和业务 owner 调用 `/api/visual-sampling`。Workbench 媒体先按固定 operation 分块转交，不假定 executor 能读取 Workbench 的本地路径。

`prepare` 是明确生成入口。`get`、读帧、读 manifest 和导出采样包只读，不启动解码、渲染、Agent 或模型。传输的 commit 只入队，由现有 pump 推进；GET 不推进。准备意图、截止、策略、owner 和 operation 固定，恢复不换 key、不刷新截止。已完成证据可以在截止后读取；中断或失败不会自动重新解码。

图片/视频学习在项目或迭代创建前即持久化准备意图，原子固定请求、来源、项目/实验标识和原截止。采样已经完成而项目尚未落盘时，同请求恢复沿用这些身份。渲染已停止后采样失败，操作明确失败并保存原媒体、渲染耗时及停止证明，不将确定失败反复当成执行未知。

原生捕获、解码样帧、供模型使用的转换图片和实际运输记录各自留存。帧有独立身份和时间，内容寻址只复用相同字节的存储，不合并不同时间点或不同角色。完成回执按同一实际请求中的独立图片 part 核验摘要、MIME、长度和数量；既有 gateway 对 job、attempt、fence 的认证检查继续执行。完成运输不等于模型理解，也不等于看过整片。

## 入口矩阵

| 入口 | 来源与策略 | 时钟及范围 | 原评价 |
| --- | --- | --- | --- |
| 图片学习 | 原上传图、渲染原 PNG、原模型副本，完整 reference/output/baseline 角色注册 | 静图不声明实测视频时刻，转换另记 | 原图片目标、评分和问题结构 |
| 视频学习 | 原视频解码与已有参考片段；保留原选帧、帧上限和编码 | 区分请求时间、可证实测 PTS 与 alias，不扩大采样范围 | 原视频/效果学习指引与停止含义 |
| 效果实验 | 渲染器保留的原 JPEG/PNG，原选择和完整送评包 | 原渲染帧、声明时刻及角色 | 原效果比较和准入 |
| 能力实验 | 既有 capture reviewer 校验后的选定标签及原字节，经私有传输登记 | 原全局时刻与序列；来源标 client retained，不冒称 executor 独立捕获 | 原盲比较、技术否决和开发者采用规则 |
| 正式影片 | 已校验 MP4 固定分块转交，保留原 24 帧预算、指定时刻、960 宽 JPEG/q4 及完整原 bundle | 原 requested decode grid，不冒称实测原容器 PTS；音频由原正式流程评价 | 原影片评价，包括原音频相关检查 |
| 动画创建实验 | 原 MP4，原短片全程采样或长片首/中/尾时间窗，原 24 帧预算 | 原 temporal sampling 的实测归一化解码 PTS | 原冻结 review profile、提示和修订次数 |
| SceneSpace | 原静图 PNG 或原片段 native JPEG/PNG；采样与评价选择独立 | 原绝对/相对渲染帧、冻结范围，静图为单张原 PNG | 新任务原评价；历史冻结合同按原记录解释 |

共用服务保留有界可配置策略，最多 240 张、单图 8 MiB、合计 96 MiB；任务可以使用更紧预算。私有媒体传输最多 512 MiB，分块 512 KiB。实际模型运输仍受各原合同限制，超限停止并保留原件，不自动删帧、缩小或降质。

Method 原 uniform 公式的短片覆盖缺陷也如实保留：3 个源帧、12 帧上限时原公式只选第 0 帧。它不证明完整覆盖；本轮不静默改变原策略。后续可在同一采样服务中独立修订选择策略和验收，不借此更换评价标准。

## 验收记录

验证使用真实 CPU 解码、已留存或确定性图片以及模拟的完成运输回执，不提交新模型、不创作和不重评历史。真实 transport、factory 和 pump 测试确认共用实例、owner 隔离、只读 GET、分块续传、同像素异时点、失败、取消与重启。原 bundle 对照逐文件核验图片及评价输入原字节一致。

测试通过、镜像构建、实际部署和服务验证分别记录，不能用本地测试代替上线事实；也不能据此补签影片质量、音频评价、WikiSkill 发布或用户艺术认可。
