# 二维过程演示：路径传递与状态变化

2026-11-05，沿用 `codex/video-audio-clock` 功能分支。本批对应 OpenSpec `improve-video-audio-clock-and-expression` 的 3.1a、3.2a；生产接线仍由 3.1b、3.2b 分别验收。

## 方向

用户要求吸收参考教程的创作方法，先与现有服务对照，不直接使用作者的 Skill、代码或渲染管线。现有 HTML/SVG＋GSAP＋HyperFrames 继续作为主力，先增强可观察的对象变化和因果过程，再补导演计划、关键画面与连续小样、独立视觉审阅及局部修订。Canvas 2D 仅在具体题材证明需要时做有界试点；Three.js 延后到明确三维需求。

二维动作基础与真实字词对齐分开推进。此前 Qwen 单次 CPU 测试因内存限额结束，没有取得可用时间；本批画面进展不改变该结论，也不代表旁白自然度或人审通过。

## 首批范围

独立 `video.process-plan.v1` 和 `motion-process-compiler-1`，以三个过程节点和同一个请求对象，演示进入队列、交给执行节点、失败返回、再次执行和完成。

- `transfer` 绑定显式有向关系，由编译器决定路径及端点，模型不提供坐标或脚本。
- `set_state` 仅选择有限状态，用文字和图形标识表达，避免只靠颜色。
- 复用受限显隐、描线、已有 beats 与明确来源的 alignment；没有把比例估算改称真实字词同步。
- 旧 motion v1、compiler1–5、demo1 与 continuity1–2 的合同和重建路径保持原版本。基础样例阶段尚未接入 Agent、数据库、采用、快照或线上工作台；后续接入状态见 [过程演示接入工作台](process-workbench-integration.md)，过程跨镜生产能力仍待完成。

## 可复查样例

```sh
python -m video_workbench.examples.build_process_sample \
  --output video_workbench/rendered/audio-clock/process/sample
```

输出目录必须尚不存在。所有本批临时输入、运行脚本、日志、截图和测试回执统一放在既有忽略目录 `rendered/audio-clock/process/`，不新增多个顶级临时目录。

这是 **24 秒无旁白技术样例**：`audio.wav` 是静音计时夹具，并非文稿的朗读。`sample.json` 明确记录 `synthetic_silence_not_narration`、estimated／pending、声音未评价、Agent／TTS 调用为 0。不能将其用于证明配音同步、语音自然度、真实模型执行或用户认可。

`preview.html` 提供播放、首帧和动作前／中／后的位置选择，读取同一份编译时间轴；需在 `assets/` 放置与验证环境一致的既有 GSAP 和字体，通过本地 HTTP 访问。预览包装页不会改变已冻结的 `index.html`。

## 验证方式

合同与编译检查覆盖非法字段、关系方向、对象身份、状态与动作冲突、可重建性及历史版本边界。真实观察检查路径起中末、完整请求对象与文字避让、状态实际文字／图形、未来线条与箭头隐藏、字体和文本溢出，以及反向归零时的状态与画面一致。

隔离渲染实验复用服务器已有 renderer 镜像内的依赖。实验直接运行单独注明的 observer 适配及 HyperFrames strict CLI；不放宽旧 `run.mjs` 的生产准入，也不把实验适配写成旧镜像已支持新合同。资源上限为 2 CPU／4 GiB，禁网、禁止拉取镜像、非 root 容器、只读容器根目录、300 秒截止，并精确清理本次拥有的容器。镜像、资产、观察适配和输入／输出摘要随实验保存。

技术检查、真人理解／节奏评价和准确旁白时序保持分开。通过几何或编码检查不能自动标记人工核准。

## 本批实测与边界

最终定向回归共 **284 项通过**，包含新合同／编译器、独立观察复核、样例生成及旧 motion、demo、continuity 的版本兼容与历史重建。本地 R8 回归此前误用当前默认编译器；测试现读取冻结 manifest 的编译器版本，未修改历史夹具或黄金摘要。最终审阅还修复了空白标签、恰好两帧及前置留白浮点消减造成合法输入被误拒的问题，真正过短的动作仍会拒绝；未改样例编译字节。测试回执位于 `rendered/audio-clock/process/tests-release-r2.xml`。

修复后的冻结输入位于 `rendered/audio-clock/process/sample-r2/`。实际隔离运行依次保留在同目录下的 `evidence/` 至 `evidence-5/`，未覆盖失败现场：

1. 初次观察适配位于外部目录，无法解析镜像既有 `playwright-core`；适配改为从 `/opt/renderer/package.json` 解析直接依赖。
2. 观察完成，但 HyperFrames 的可用磁盘检查拒绝 768 MiB 的 `/tmp`。CLI 临时目录改至本次独立 `/work/tmp`，未放宽检查或内存上限。
3. 实际画面暴露标题行高不足与描线取整跳现，分别修复标题尺寸和 `autoRound:false`，重建为 `sample-r2`。
4. 修复后的编码成功，但下载白名单遗漏 DOM 观察 JSON；该次不能作为完整语义验收证据。
5. 补齐证据打包后，复用完全相同的 `sample-r2` 冻结输入重跑。observe、strict encode、probe、完整 decode 均成功；实际耗时约 49.21 秒。容器已按本次所有权精确清理。

独立正式观察复核通过：16个动作窗、50份DOM样本、51张截图及全部输入／产物摘要相符；六文件重新编译完全一致。首帧与反向回到首帧一致，所有动作前／中／后均核对完整token位置、状态文字／符号、线条可见性和文字边界。这是所记录动作窗和首尾反向定位的实测，未穷举所有可能的seek顺序。

成片为 **1280×720、24 fps、24 秒、576 帧**，无音频流。WAV 仅是输入时钟夹具，成片没有配音。使用已有 `video-motion-renderer:latest@sha256:a39f5e41fd2fba6aeaba28a1e04eea0e057d6a98fcd087b9cb626e6ef7a3814a` 的依赖，HyperFrames 0.8.149、GSAP 3.14.2、Node 22.20.0、Chromium 149；本次容器 `memory.peak` 为450,756,608字节，不等同于生产并发或任意题材资源需求。资产、实验观察适配及输入输出 SHA 均保存在证据中。汇总见 [可追溯技术回执](../samples/process-motion-foundation-20261105.json)。

画面仍是固定三节点／单请求／三条有向路径的受限样例，线条在队列锚点共享端点、终态队列仍显示等待，后续导演计划和视觉审阅应改善这类表达。该基础样例不证明任意长文稿生成、跨镜新动作、手机可读性、完整预览／导出一帧一致、旁白同步或语音自然度；此阶段尚未接入生产接口及用户审片功能，后续工作台接入另行记录。

## 用户反馈：节点与连线的位置

用户认可动作展示，但指出框图位置不对。复看上一版可见：关系端点在y328，卡片顶端在y452，相隔124px；三个节点成为了下方的说明牌，没有与上方过程形成完整框图。此前位置和遮挡检查未覆盖“可见关系必须接到节点边框”，技术通过没有解决这一表达问题。

本轮增加独立 `motion-process-compiler-2` 布局。三个节点统一放在中部，正文、状态和请求停靠区分开；请求从卡内停靠区经过真实边框端口到达下一节点。失败返回使用节点底部端口和下方回程，避免与正向箭头共点。

可见连线与请求中心的完整移动路径分别冻结，并核对共享的外部路段。请求可以进入专用停靠区，完整边界仍须避开正文、状态和关系标签；实际SVG端点、卡片边框及停靠区从浏览器DOM测量，不以自报坐标替代。上一版compiler1和证据保留，按明确版本重建。

修正版冻结输入为 `rendered/audio-clock/process/sample-layout-v2/`，实际运行保存在同根 `evidence-6/`。330项最终定向回归通过，包含显式v1六文件逐字节重建及新版本端口、停靠区和正文避让。严格观察16动作窗、50份DOM、51张截图通过；编码后的6张实际MP4抽帧另行核对正向、回程、初始和终态。实片1280×720／24fps／24秒，ffprobe实读576帧，完整解码通过。五阶段约49.81秒、容器内存峰值446,717,952字节，所属容器清理确认，未调用Agent／TTS或写生产业务数据。

固定CSS和编码后实片中的边框可见，真实DOM矩形与SVG端口几何相接；机器几何检查本身不证明任意CSS的边框可见性或像素遮挡。当前marker有约2px尖端伸入节点背景的微小样式边界，方向在实片可辨。终态队列仍显示等待等内容表达限制继续保留。可追溯摘要见 [框图布局反馈回执](../samples/process-layout-feedback-20261105.json)。

用户随后确认修正版布局“可以了，继续”，本次动作与框图方向获认可；这不等于整体讲解、旁白时序或上线验收。该技术样例仍为无旁白，后续工作台接线见 [过程演示接入](process-workbench-integration.md)。
