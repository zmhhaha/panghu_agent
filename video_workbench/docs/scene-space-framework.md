# 场景空间公共核心

本模块实现“先规划，再绘制”的公共数据与数学基础。它承接映射 OpenSpec 项目
`ec663f5a-53d3-4a0e-9037-933eb788d183` 中的
`add-scene-space-layer-camera-learning`。本轮范围为阶段 1：公共框架。

图片制作、视频制作、参考学习和效果库的阶段 2 接入已另行实现，范围与运行准入见
[接入说明](scene-space-integration.md)。公共核心本身不注册新执行能力、不执行绘画
配方；单独通过其测试不表示后端、部署或艺术验收已通过。

## 世界、镜头与执行区间

- **场景世界**保存稳定对象、局部坐标与父子变换、锚点、占位范围、显式深度、图层、
  布局辅助和空间关系。对象级配方引用仅用于身份与依赖追踪。
- **镜头计划**引用同一世界，描述固定主观看方向下的平移、有限推拉、停留及允许的
  局部动态。固定镜头和没有局部动态都是合法选择。
- **执行区间**用于适配现有每段不超过 60 秒的时钟限制。拆分执行不产生新世界，
  求值仍使用全局绝对帧，因此同一帧不受播放顺序或分段边界影响。

首版保留 24 fps、最多 300 秒的总体规划边界。这里的规划容量不自动扩大任何实际
执行器的尺寸、时间、内存、接口或依赖准入。

## 空间语义

世界坐标、局部锚点和可用画面范围与输出画幅分别表达。仿射矩阵使用 Canvas 的
`[a,b,c,d,e,f]` 顺序；角度使用度。父子关系用于计算世界坐标，图层和对象的顺序
用于表达绘画前后，显式关系约束其一致性。

布局网格和点集用于构图、占位、接触点与比例规划。它们不是墨色密度计算网格，
也不是将所有笔触转换成三维点云。逻辑深度、几何深度和未知深度分别保存，画面
Y 坐标不推导景深。水墨散点透视、平面层级与几何场景可以选择各自的空间规则。
公共预演使用固定主观看方向下的仿射投影，镜头 `x/y` 表示世界坐标中的取景中心。
`geometric` 深度标签保留给后端适配，本轮公共诊断不从平面布局重建真实三维结构。

校验关注重复或缺失身份、父子和关系循环、浮空锚点、支撑区域、比例约束、矛盾的
遮挡顺序、无效数值和有界资源。景物可以有意越出可用区域，但需在数据中明确。
图层数量、墨色、清晰度和虚实不由一个强制的“三层画法”决定。

## 计划、预算与修订

自动规划根据给定世界、创作意图、焦点、动静选择和平台预算生成有界镜头和执行
区间；随后在绘画前检查取景范围、推进倍率和所需缓存规模。它不提供用户逐镜头
手动编辑或确认入口。全自动制作入口如何产生这些意图，由后续适配接入负责。

求值仅依赖计划、绝对帧与固定种子；重复、反向或跨区间查询同一帧得到一致状态。
模型与渲染预算分别记录，未知实际用量保留未知。计划修订保存原因和新版本，
计算受影响的对象、图层、镜头、缓存和检查；已发生的成本随谱系保留。
技术恢复要求原冻结计划身份一致，不能通过修订重置预算。

`scene_space_budget` 将运行消费与冻结计划分开：`create_usage` 建立片内任务账本，
`record_usage` 按唯一事件 ID 累计生成、评审、协作、修正、预演、渲染和失败成本，
`bind_revision` 将原账本绑定到已校验的新计划，`prepare_retry` 保留原计划和全部消费。
同一事件重复提交幂等，修改同一 ID 的测量值会拒绝。已发生的超支仍记录，后续导出
准入停止；事件槽、剩余时间或 token 测量不满足条件时，也不能启动正式导出。

token 上限是有限整数，实际 token 用量和渲染耗时可为未知。调用或渲染没有测量时，
账本不会补成零。`require_export_budget` 检查累计成本并可为导出预留时间。这是纯数据
与准入计算：实际用量采集、可信账本持久化、并发写入及停止执行由阶段 2 的宿主接入
负责。摘要用于内容身份，不能充当认证或“已经测量”的证明。

本轮没有全局场景资产池。片内世界复用不等于跨影片自动继承旧山、树、布局或
缓存；效果精选和 WikiSkill 发布仍遵循各自明确的操作边界。

## 布局预演与证据

`agent_service.scene_space_contract` 提供世界合同与几何校验；
`video_workbench.scene_space_plan` 提供镜头、区间、预算和修订核心；
`video_workbench.scene_space_preview` 输出低成本布局 SVG 与分项报告。

布局图中的颜色用于区分对象与图层。区域遮罩以轮廓表示，网格仅在请求调试时显示。
SVG 不解析或执行 `recipe_ref`，也不替代实际水墨绘制、光照、透明度合成和像素验收。
报告将数据/几何检查与画质、连续运动、音频观察分别记录。几何成立不能自动成为
艺术评价，静态布局也不产生新的镜头观察事实。

世界布局预演的调用方式：

```powershell
python -m video_workbench.scene_space_preview tests/fixtures/scene_space/world.json --output D:/codex-work/scene-layout-preview --grid
```

输出目录须为新目录，避免用新失败报告覆盖旧预览。产物包含原世界身份、诊断范围和
文件摘要；无效世界只输出诊断，不产生会被误认为当前有效布局的 SVG。

镜头预演使用 `--plan`。它选择镜头边界、执行分段边界、轨道关键帧及中间样本；
最多 256 帧、单图 4 MiB、采样 SVG 总计 32 MiB。必要样本超预算时输出失败诊断，
不悄悄漏掉边界。镜头布局展示投影后的占位和锚点，不实施像素绘画或遮罩合成。
取景及缓存覆盖由公共计划计算；需要的像素与临时表面内存为规划估算，实测渲染资源
和实际像素清晰度仍需后端验证。

## 可运行示例与 API

```powershell
python -m video_workbench.examples.scene_space_demo --output D:/codex-work/scene-space-demo
```

示例读取随代码提交的测试世界，自动编排三个镜头，复用同一个世界。180 秒的规划
被拆成四个执行区间，包含停留、有限推进和静机位的局部透明度变化；示例不生成视频。
输出世界布局、12 个镜头布局样本、冻结计划、摘要报告及一个无效父子循环的反例。
示例中的山、树、图层与动态仅用于演示，不是公共框架强制的创作模板。

| 模块 | 主要 API | 用途 |
| --- | --- | --- |
| `agent_service.scene_space_contract` | `validate_world`、`world_sha256`、`world_geometry` | 规范化身份、空间约束及仿射几何 |
| 同上 | `grid_point`、`layout_point` | 按网格或命名点查询位置，保留显式/未知深度 |
| `video_workbench.scene_space_plan` | `automatic_plan`、`validate_plan`、`freeze_plan` | 将宿主选择的创作意图编译成完整有界计划 |
| 同上 | `compile_evaluator`、`evaluate_frames`、`split_intervals` | 绝对帧求值及不重置时钟的分段 |
| 同上 | `required_coverage`、`revise_plan`、`technical_retry` | 覆盖、依赖失效及冻结恢复 |
| `video_workbench.scene_space_budget` | `create_usage`、`record_usage`、`usage_status` | 独立累计消费，不随修订和恢复清零 |
| 同上 | `bind_revision`、`prepare_retry`、`require_export_budget` | 谱系绑定及预算准入 |
| `video_workbench.scene_space_preview` | `write_world_preview`、`write_plan_preview` | 布局诊断与有界采样预演 |

自动规划 API 是宿主内部数据编译器，接收世界和创作意图；正式入口如何根据目标选择
世界、场景数量和意图，属于阶段 2 的编排适配。首版没有用户逐镜头编辑接口。

## 阶段边界

阶段 1 的测试和预演证明公共合同、空间数学、规划和可重放性，不代表 Canvas、
SVG/HTML、Three.js 已完成共同执行适配，也不代表线上水墨视频、真实时间观察或
五分钟长片已验收。后续接入必须继续保留旧静态/抽帧合同、原依赖身份、历史恢复
和知识开关的含义。

转换会让旧扩展的严格字节校验失败，不能通过改 pin 绕开。代码与知识合同没有因此
变更。示例只调用确定性的框架代码，未调用模型或绘画配方，也没有导出成片。
