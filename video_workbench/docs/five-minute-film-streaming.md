# 五分钟整片的有界连续捕获

正式整片可选择最长 300 秒、24 fps 的新批次，单镜最长 60 秒及既有 24 镜上限保持。正式预检同时要求执行器准确的镜像、runtime、host 摘要、执行准入和 `capture_modes` 中的 `streaming-png-v2`；仅提高客户端时长不构成准入。

## 同一工程、一次编码

超过 1440 帧的工程使用 `video.hyperframes-film-frame-capture.v2`。浏览器仍沿同一根 HyperFrames 工程逐帧定位完整全局时钟，每张 PNG 直接通过有背压的 stdin 写入一个 FFmpeg 进程。一次 pipe 写完才接收下一帧，帧文件数量为零；不生成逐镜 MP4，也不将几段短片拼接成电影。源 WAV 仍由统一原声时钟混音，显式无旁白工程保留真实静音区间和 `contains_narration=false`。

长片根配置冻结 `capture_lifecycle=persistent-active-modules-v1`。进入镜头时挂载模块、离开镜头时释放，最多同时保留两个镜头及一个转场。模块可在 mount 中预计算不变底稿，renderAt 必须根据绝对帧合成状态。每帧仍执行原有的延迟静置双截图检查；末帧、逆向首帧和中帧探针先释放全部 realm，再从新模块实例重建并核对 PNG 摘要，缓存不能掩盖不可重建的状态。

## 资源与取消

- 最多 7200 帧，每张压缩 PNG 不超过 12 MiB，累计处理 PNG 不超过 16 GiB；累计量不写入磁盘。
- 编码器最多排队一个完整 PNG；浏览器截图、静置截图和系统 pipe 仍各有有界暂存，不能将此数字当作整个进程的峰值内存。
- 成片仍限制为 128 MiB。长期捕获的 JSON 回执限制为 64 MiB；旧短片回执保留 16 MiB。
- 旧短片制作默认 600 秒预算，新长片最高 3600 秒。每帧静置检查本身使 7200 帧至少需要约 12 分钟，实际执行预算必须包括源码绘制、浏览器截屏与编码，不能按成片时长估算。
- 既有取消及超时继续终止整个拥有的进程组和 Kubernetes Pod；Node 捕获异常时也显式停止并等待唯一编码器退出。取消完成以前，原持久执行记录保持未停止状态。
- Job 继续使用 2 GiB scratch 限额，不保留全片 PNG；输入包、交付 WAV、成片、回执和 Chromium 工作目录的真实峰值仍需目标主机测量。

## 保留的旧行为

1440 帧以内继续使用 v1 完整 PNG 库存和原回执，原根配置仍逐次重建 realm。历史冻结批次保存自己的 60 秒上限、镜像和时钟；技术恢复不替换其 release。新长片通过额外根配置、捕获 v2、stream storage 清单及实例重建证据明确区分，不把历史短片回执解释成流式执行。

验证范围分开记录：Node 测试检查真实 PNG pipe、单次 FFmpeg 动态媒体、完整时钟、停止与不覆盖旧文件；Python 的 61 秒检查使用合成帧运输和真实编码/完整解码，不能作为浏览器或艺术验收。新镜像仍需真实核心/原生 Canvas 的超过 60 秒导出，以及用户 300 秒作品的整片审阅。
