# 通用协作与创作指导

2026-11-16。协作是创作任务的组织方式，绘画与动作工具是执行能力。协作不应绑定 Canvas、水墨、固定图层或固定角色；是否能使用某项能力，仍取决于当前任务实际冻结的准入与资源。SVG/HTML、Canvas 2D、Three.js 可沿用同一套统筹、职责依赖与整合协议；GSAP/Anime.js 继续遵循已准入的绝对时钟规范。Manim 等预制资源仍须先完成既有资源生产步骤，通用协作不代表绕过这一依赖。

宿主负责范围、预算、身份、依赖调度和 HyperFrames 渲染；Agent 自主决定画法和职责分配。不能因为多个 Agent 完成了源码，就推断样片比单 Agent 更好。

## 冻结的创作指导

`video_workbench/creative_direction.py` 提供 `build_creative_direction(...)`，生成 `video.creative-direction.v1`，供宿主写入操作输入的 `constraints.creative_direction`。这是已有 v1 合同允许的有界任务上下文，不修改冻结 profile、提示词资源、工具或结果结构。

指导要求统筹先识别作品不可丢失的表达和风格特征，并将其转换为具体可观察标准。已有标准必须原样保留。构图更清楚、技术通过、代码更多，都不能抵消核心风格失败。不同画法由 Agent 按实际目标选择；工程代码不规定水墨算法、景物清单或统一模板。

职责之间需要共同定义形体、材质、坐标、参数、绝对时钟和随机种子。若多个部分的外观紧密耦合，应明确共享造型或材质原语的归属以及实际依赖，避免每个组件各自近似同一种风格。整合 Agent 必须解决边缘、遮挡、质感和节奏的差异，不能只拼接组件。关键画面的文字计划只表达待检查状态，不是已经渲染或通过的视觉门控。

继续优化时，同一指导保留基线候选及源码摘要，提醒 Agent 保留有实际证据或开发者意见支持的优点。基线策略只是作者意图，不能凭源码自动推断“已观察到的优势”。必要时可以大改表达机制，但需说明得失；没有自动要求保守小改。

## 反馈与上下文边界

原始目标、标准和本次反馈继续保存在原操作输入字段；完整历史意见保存在原反馈 API。指导仅绑定这些输入的 canonical JSON 摘要，不重复整套源码、Wiki 或历史操作。

指导最多 8 KiB，最多代表最近四条未撤回意见。能放入的评论逐字保留；单条太大时整条正文省略，保留摘要、原始 UTF-8 字节数及 `omitted_size_limit` 标记。极长合法标识使元数据也无法容纳时，整条移出并记录数量。输入、代表、正文纳入、正文省略、因大小未代表、已撤回和更早意见的数量均明确记录，完整输入也有摘要绑定。不会静默截短原话，更不会把 Agent 改写的摘要当成用户原话。比较意见保留两条实际候选及选择，仍只属于开发者判断，不会变成独立视觉检查或发布认可。

宿主应将该指导与操作输入一起冻结；重放既有操作使用原输入，不在同一操作中重新查询实时反馈。新请求或新评审冻结输入时排除已撤回意见；随后发生的撤回不改写既有冻结任务。此模块不获取数据库、不执行模型、不渲染、不发版，也不增加实验预算。

## 判断与验证

评判先检查实际目标与每项冻结标准，再分别记录新旧样片得到了什么、丢失了什么。静帧不足以证明连续动作、节奏、声音和声画配合；证据不足不能写成通过。创作指导只改善 Agent 的决策上下文，真实提升仍需实际生成、完整观察和开发者比较。

专用测试验证输入保真、摘要绑定、上下文上限、撤回过滤、技术中立和 v1 合同兼容，不代表已产生更好的画面或完成线上多能力协作验收。
