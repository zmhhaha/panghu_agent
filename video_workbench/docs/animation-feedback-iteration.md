# 动画反馈到 GitHub 的开发迭代

服务器开发者工作台入口为 https://video-service.panghuer.top/dev/animations/ 。在顶部展开“反馈迭代”，按框图、过程、跨镜、Canvas 或 Three.js 分别查看意见并准备开发任务。普通视频制作流程没有增加步骤。

## 从意见到任务

工作台汇总当前有效的问题、版本偏好、人工审阅，以及自动评测中已确认需要修改的问题。每条意见保留原样例或评测报告身份、版本、时间、区域、产物和资源摘要。历史画面上的意见会注明来源，不会自动变成对当前画面的判断。

“生成增量任务”会保存一份轻量 JSON。它包含当前有效意见和相对上次明确同步的新增、修改、失效记录。撤回和改判也会反映到增量中；此前被替代的偏好在新意见撤回后可以恢复有效。任务不内嵌音频、HTML、字体或 Base64 冻结产物；需要复现时沿证据链接读取原记录，并匹配原资源摘要。

生成或下载不表示已经调用 Agent、修复问题或推送 GitHub。只有独立执行器实际接收并登记同步回执，才推进模块的已同步位置。重复准备相同增量会返回已有任务；准备期间意见改变会明确冲突，需刷新后核对。

## 独立执行器

独立开发执行器使用显式选择的源码窗口、Git 基准和模块允许列表。在隔离 checkout 中读取原始源码摘要，让已授权的通用 Agent 返回有界结构化修改提案，校验后应用并执行固定模块测试。GitHub 凭据只在执行器环境中配置，工作台 Pod 没有 GitHub/Agent 凭据、Git 写入口或出站权限。

现有 video-workbench 调用方只获准使用 video profiles，不能直接借用其令牌调用通用文本任务。执行器须显式配置独立调用方及其可用的 `workspace-task.v1` profile。未配置、能力未授权、源码窗口超过限制或依赖环境缺失时停止，不自动创建模型任务或静默截断输入。

使用命令和 Agent 配置见 [独立开发执行器](animation-feedback-runner.md)。命令行将准备、提案、应用、测试与发布分别执行；发布只创建独立 `codex/` 分支和 draft PR，不合并或部署业务模板。

## 记录进展和验收候选

执行器输出的事件 JSON 可在反馈面板登记。回执绑定任务身份、模块、源码版本和独立运行，具有幂等键与预期状态；冲突不会覆盖原记录。状态包括已准备、已同步、开发中、PR、候选待验收及通过/需改进/失败/取消。外部登记的回执明确标为外部报告，工作台不会将自报测试结果伪装成独立验证。

已发生的 PR 等外部事实可以在意见变化后继续登记，但面板会显示任务与当前意见不一致。开发开始和候选通过需要仍匹配当前反馈。PR 只链接本仓库，候选入口限制在同源开发者工作台；候选还必须带对应提交和检查结果。

候选必须指向已发布的真实冻结评测，并附 `iteration-candidate.json` 发布绑定。工作台重新读取实际报告、产物摘要和绑定文件，核对任务、源码、提交及样例；一个未被页面读取的查询参数不能充当候选。旧评测格式没有独立的源码构建证明，因此这里验证的是冻结资料及开发者登记的提交关联，不宣称已独立证明该提交构建了画面。通过时再次核对，报告或绑定改变会被拒绝。

面板展示该候选覆盖和未覆盖的意见。单个案例的报告不能批准任务中的其他案例；未完整覆盖时不能将任务标为通过，仍可查看候选并记录需改进。具体拒绝原因留在任务历史；需要让下一轮采用时，应在对应候选中保存精确的问题标注，再准备新任务，原任务的显式重试不会隐式吸收这条说明。

“样例通过”只代表这一开发候选的人工验收。它不表示生产模板已经采用，不合入主线，也不自动核准语音、旁白时序或任意文稿的效果。

## 数据与代码

GitHub 保存代码、测试、小型任务摘要和对比结论。SQLite、完整历史 JSONL、原始采样图和冻结产物继续保存在服务器持久卷；完整导出包含新增的任务和事件，仍用于备份而非每次代码提交。原历史记录和冻结身份保持。

相关接口均位于已登录的 `/dev/animations/` 下，沿用开发者身份、固定 Origin、CSRF 和有界 JSON 写入检查：

| 接口 | 用途 |
| --- | --- |
| `GET api/iterations?module=canvas` | 模块有效意见、增量和任务历史 |
| `POST api/iterations` | 绑定所见 cursor 准备任务 |
| `GET api/iterations/{task_id}` | 任务、状态和事件 |
| `GET api/iterations/{task_id}/export` | 下载轻量、摘要绑定的 JSON |
| `POST api/iterations/{task_id}/events` | 登记同步、开发、PR、候选或人工验收事件 |

镜像在构建时保存实际 Git 源码身份。源码身份未知的本地实验可查看反馈，但不能宣称已经具备可执行的代码基准；本地启动可通过 `--source-revision` 显式提供已核对的提交。

OpenSpec 变更为 `add-animation-feedback-github-iteration`；实际源码检查、部署和浏览器验收分别记录，真实模型调用与真实 PR 发布不以模拟测试代替。
