# 复杂效果的职责协作创作

2026-11-16。本方案用于验证：把绘画职责和必要上下文分给多个 Agent，能否改善水墨等复杂材质、空间和氛围表现。它不是固定山水模板，也不是面向用户的图层编辑器。

协作入口已完成独立准入并上线，同题水墨实验已走通统筹、三个职责组件、整合与 HyperFrames 完整渲染。新样片仍有明显多边形块面和笔墨不足，不能据此认定美术目标达成。实际部署、调用和对照范围见 [发布与验证记录](collaborative-effect-validation-20261116.md)；前置关键画面检查门控仍待实现。

2026-11-17 已确认的新创作模式及知识加载边界见[从零重做与技能加载](fresh-rebuild-and-skill-loading-design.md)。下文保留原协作实现和验证范围；新增从零隔离、严格技术重试及卡片人工采用尚待实施。

## 创作流程

1. 统筹 Agent 生成统一的构图、材质、空间、时钟和接口约定，以及 2～4 个职责组件的有向无环依赖图。职责由 Agent 根据表达目标确定，不由工程代码固定成山、雾、树。
2. 宿主按依赖调度组件 Agent，最多两个组件并行。每个组件只收到精简全局约定、自身职责、直接依赖源码和必要方法；不附带整套 Wiki 或全部历史操作。
3. 整合 Agent 获得全部组件，自主组织完整的 `scene.html/js/css`、音效事件和方法草案。宿主不机械拼接未知接口，也不代写创作源码。
4. 通过既有 HyperFrames 路径渲染一条完整样片，使用真实产物抽帧评审，开发者再评价完整播放效果。子组件不产生独立效果卡片，不默认分别生成 MP4。

SVG/HTML、Canvas、Three.js 仍是绘画能力，GSAP/Anime.js 是动作编排工具；协作是创作任务的组织方式。原首版业务适配层曾限制 Canvas，本次移除该限制，严格保留每个任务冻结的准入能力；计划、组件、最终源码及 Skill 声明须一致。纯协作核心不识别绘制技术、画幅或渲染，视频适配层负责这些约束与 HyperFrames 交付。Manim 等资源预制作仍使用原有资源生产流程，暂未与此协作入口合用。工程支持与真实分引擎验证分别记录。

## 任务与成本

结构化 API 显式传 `collaboration: {"max_components": 3}` 开启；未传则沿用普通实验。上限为 2～4；一次委托固定一版，`budget.max_rounds=1`，创作额度预留 `max_components + 2` 个操作（统筹一次、部件最多 N 次、整合一次），另有一次最终渲染和一次评审。操作额度不等于底层模型请求次数；新 profile 每次 attempt 最多十个模型请求，宿主更严格的配置优先。

所有阶段共享同一委托、原截止时间和持久预算。提交响应不确定时只查找原 operation，不换身份重新付费。取消、失败和超时先停止或释放同委托的其他活动任务，核实停止后才终结委托。继续优化是开发者另发委托，保留协作设置；重跑也保留原配置。该限制不改变效果库可持续优化、也不改变正片一轮自动打磨加最多两轮用户追加的规则。

新身份为 `video.animation-collaboration.v1`，独立 caller 和凭据；不伪装成旧作者 profile。结果保留真实输入哈希、阶段、直接依赖及源码。只有最终整合源码进入原候选、方法和渲染证据链。不会自动认可样片、迁移结论或发布 WikiSkill。

## 交互

新建实验的高级选项提供协作开关，默认关闭。只有服务侧独立准入并启用时才可提交。详情只读显示统筹、部件、整合、渲染和评审阶段，以及已占用的创作操作额度。普通用户的视频制作流程不因此增加手动图层操作。

## 首个验证对象

同题 Canvas《雾退见山石》，重构近石线束感、重复远山和缺乏顺势皴纹的问题。参考研究提取的是视觉原则；外部视频网址、下载资产和外部代码不成为生成作品或 Skill 的运行依赖。换主题或换技术应建立独立效果。

检查应区分：构图、近深远浅、形体与皴纹的结合可由关键静帧辅助判断；雾的移动、成画过程、鸟群和视差必须连续播放评价。没有完整观看或开发者认可时，不能记录为同等水墨质感已经实现。

## 验证边界

协议、调度和合成单元测试使用合成任务、无效媒体夹具，只证明工程行为。真实技术候选只证明所运行 phase 的输入输出、隔离及停止，不证明全部阶段、画面质量或完整动画。

当前 `keyframe_times` 是统筹的时间约定。最终视频抽帧不等于“先验收关键画面、通过后才制作完整动画”。真正的先行视觉门控尚待独立实现和验证，不在本轮技术测试中冒称完成。整库 WikiSkill 编译超时的问题也保留为独立未完成项。

## 通用协作与质量决策

通用调度、视频适配、创作指导与质量选择分别由 `creative_collaboration.py`、`animation_collaboration.py`、`creative_direction.py`、`animation_quality_policy.py` 承担。既有普通继续优化的协作委托在收费操作前冻结有界指导，强调核心表达、共享材质与职责依赖；基线源码只在整合阶段提供，开发者意见保留原文与证据范围，不加载整套历史。这是普通继续优化的继承行为，不是从零重做的隔离规则。当前复用同一 v1 协议，不改写冻结 profile 或 bundle。

自动评审保留模型原始结果，另存宿主选择依据。有可用基线时，明确失败的标准阻止新版自动晋升；证据不足不等于质量退步，但不能支持“全部目标达成”。动作或音频尚未观察的标准不能在方法验证汇总中记为通过。后续评审使用其输入冻结的确切候选对偏好；保存反馈本身不触发改选，也不回写历史评审。界面展示保留基线或证据不足的原因。以上机制不保证一次生成就达到审美目标，也不代替真实播放和开发者评价。

## 新模式的上下文与采用边界（2026-11-17 确认，待实施）

同一效果下可以另开从零重做实验，效果归属不触发源码继承。新创作只带本次目标、用户要求及精简的可靠问题摘要；未验证推测保留为待检查项。旧源码、布局、专用方法和职责分工都不进入规划、部件、整合或 Manim recipe 的创作上下文；不能只清空组件方法，却让整合阶段重新收到旧源码。新实验内部按依赖生成的组件约定和源码仍可正常共享，不受旧作品隔离的限制；这不表示当前协作入口已经支持 Manim。

从零重做可以重新制定验收标准。用户填写时按本次要求处理，留空则由 Agent 拟定、记录并继续，无需等待确认。所有制作默认加载 WikiSkill，网页和 API 可关闭；选择与创作模式独立，关闭仍保留技术接口、准入及 HyperFrames 运行规范。各角色遵循本次冻结选择，不从旧基线或依赖中偷偷恢复被关闭的知识输入。

技术重试保留原需求、已完成方案、职责 DAG、验收标准和 WikiSkill 设置，复用有效成果，只修复或恢复失败环节。重试不重新划分职责、不改变创作方向，也不随线上知识更新换版；方向改变应另开实验。未知提交仍先查询原任务，停止证明和实际预算继续按原合同处理。

委托内部的 `best` 或候选晋升是实验判断，不等同于效果卡片默认作品的人工采用。从零重做完成后先保存候选及历史，开发者比较后明确决定是否替换默认展示作品；完成、内部判优或卡片采用均不自动发版 WikiSkill。每次实验有自己的预算，开发者持续优化不受正式制作 1+2 打磨限制。
