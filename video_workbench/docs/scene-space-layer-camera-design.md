## 目标与已确认的取舍

把逐段分别造景，改为先统一规划少量完整场景的空间、镜头和局部动态，再按可见范围准备绘画与复用结果。图片学习、视频学习、效果库和正式创作共用这套空间描述与证据语言；绘图与渲染实现保持各自特点。减少模型重复编写场景的开销，与减少逐帧合成、捕获、编码的开销分别测量，不承诺设计本身就能达到某个帧率或节省比例。

| 讨论项 | 已确认决定 |
| --- | --- |
| Q1 镜头自由度 | 固定主观看方向下平移和有限推拉；明显绕行、物体背面和完整三维重建不在首轮范围。 |
| Q2 空间连续性 | 同一场景内对象身份、相对位置、尺度和遮挡关系跨镜头保持连续。 |
| Q3 通用范围 | Canvas、SVG/HTML、Three.js 共用上层构图、空间关系与镜头意图；各后端实现各自绘制与投影，首先验证 Canvas 山水。 |
| Q4 必要修正 | 允许在预算内修好底景、前景和局部对象，然后复用；不靠增加新场景数量补足时长。 |
| Q5 影片组成 | 少数完整场景，每个场景多个镜头；不按固定时长强制换景，首次验证只用一个场景。 |
| Q6 布局粒度 | 山、树、坡岸等对象是主要规划单元，网格辅助布局；对象内部笔触保留局部坐标。 |
| Q7 编排方式 | 全自动编排，不新增逐镜头局部编辑入口，也不要求用户逐镜头确认。 |
| Q8 动静选择 | 是否运镜、固定机位配局部动画、或其他允许的组合，由开头的全片规划决定；不预设必须运镜、飘雾或添加飞鸟。 |
| Q9 复用边界 | 本轮只建立片内复用。好的效果通过效果库精选留存，再经显式 WikiSkill 发布影响后续创作，不建立自动跨影片场景资产积累。 |
| Q10 质量门控 | 先做低成本布局、关键帧、短预览和自动检查，再完整导出；修正有界。 |
| Q11 失败处理 | 预算耗尽仍未达标时停止正式成片流程，保留最佳预览和问题说明，不把可播放当成画质通过。 |
| Q12 空间规则 | 通用对象语义配合按风格选择的网格、投影和构图规则；不将画面 Y 坐标直接等同深度。 |
| Q13 预算来源 | 平台设置上限，系统自动分配，用户可收紧；可以重新分配剩余预算，不能自动提高总上限。 |
| Q14 计划约束 | 统一计划约束执行。重大变化须形成新计划版本，并重新检查受影响部分；全过程自动完成并保留原因。 |

用户随后明确扩展：现有图片学习、视频学习和效果库也应使用上述能力，在学习过程中逐步学习空间、分层、遮挡，以及视频中的镜头移动和局部动态。扩展不授权本次文档任务生成作品、修改运行合同或发布新 WikiSkill。

## 现状与真实缺口

本节及末尾代码定位描述来源视频分支 `faaa09affca3205ecfa46b2204f8d6aa2a017362` 的状态；不描述本次仅合入文档后的主线能力。

已交付山水片的十二个模块已经包含镜头计算、按深度合成、静态画层缓存和局部动态。问题不是完全没有图层或镜头，而是这些逻辑分散在模块源码中，尚无共同的场景空间语义和跨镜头复用约束。正式恢复任务复用了十二个模块，没有新作者任务；它仍需捕获并编码 7200 帧。更换镜头不能消除这部分导出成本。

现有正式时钟要求每个场景区间不超过 60 秒，本次长片上限为 300 秒；模块运行于各自隔离环境，不能假定其活对象或缓存天然跨模块共享。分层缓冲当前可用 detached HTMLCanvas，运行边界禁止真正的 `OffscreenCanvas`；原绘图库的 `renderCanvas` 会重置变换、透明度、滤镜和合成状态。这些都是后续实现必须遵循或显式新版本准入的边界，本文不放宽它们。

图片学习旧合同只具有静态证据。视频参考学习旧 v1 的 `sampled_frames_only` 输入明确将 `motion_observed`、`audio_observed`、`whole_video_watched` 保持为 false，结果也保持抽帧证据范围。当前合同不能因增加镜头描述就被解释成已观察运动；实际时间证据与运动验证需要独立的版本化扩展。

## 一、共同描述：场景世界、镜头、执行区间

下列名称表达待实现的概念，不是已经上线的 API 或数据库字段。

**场景世界（SceneWorld）**保存稳定标识与版本、坐标约定、画幅和可用绘制范围、对象集合、空间关系、构图区域及风格约束。一个场景世界可以支持多个镜头和多个执行区间；执行区间变化不自动触发作者重写完整景物。

对象描述包括稳定 ID、类型、父组、世界或分层局部位置、根部等锚点、占用范围、尺度范围、深度表达、绘画配方或来源引用，以及必要的依附和遮挡关系。例如树根落在坡岸上，叶片依附枝条，船落在江面区域。深度允许二维场景中的序位或逻辑深度，以及三维场景中的几何深度；来源不足时可记录未知、区间与置信度，不伪造精确三维坐标。

**镜头（Shot）**引用场景世界与计划版本，声明绝对时间区间、观察区域、焦点、允许的平移和推拉路径、停留与缓动、对象可见性，以及所需局部动画。静态镜头是合法结果，局部动态也可为空；规划器根据目标和风格选择组合。

**执行区间（ExecutionInterval）**服务于现有调度、模块和导出限制，引用确定的世界与镜头计划。一个镜头可因执行限制拆成区间，同一世界可供多个镜头引用；拆分必须保持绝对时钟、对象身份与画面连续。实现时选择有界的数据或资源引用与缓存策略，不能假定现有隔离环境能够共享活实例。

## 二、网格、点集与分层

网格用于构图锚点、区域、地面或水面、尺度关系和可见范围的规划与调试。点集优先表达对象锚点和约束关系，不把整幅图像像素化成所谓三维点云，也不把每根笔触都升级成全局场景对象。网格默认不出现在最终作品中。

按风格选择空间规则：水墨可以使用散点透视、留白、虚实和局部深度分组；平面插画可采用重叠、比例和层级；Three.js 可使用真实几何与相机投影。共同检查对象依附、尺度和遮挡的一致性，不强迫所有作品服从单一消失点。

远、中、近景是可选的组织方式，不硬性限定恰好三个图层。图层与对象分组共同表达绘制顺序、深度、局部遮罩、风格参数和视差。墨色、干湿、纹理和清晰度按画意配置；不强制前景极黑、远景统一透明，也不把简单降低全层透明度等同于景深。

雾与留白可以柔化局部接合。遮罩应作用于明确的对象或图层，保持纸面和后景正确合成；禁止为了隐藏接合问题在最终画布上造成透明洞、整齐白色切口或必加白晕。遮挡图、依附关系与投影约束须能发现悬空对象、错误盖层、尺度突变和循环关系。

## 三、全自动编排与有界绘制

在昂贵绘制前，统一规划场景数量、对象与空间关系、各镜头的覆盖区域、最大推进范围、动静组合和可复用内容。随后准备足够的画面范围与细节，并在低成本预演中验证。既不先生成大量互不相关的画面再拼接，也不依赖无限放大一张图掩盖内容不足。

镜头调整优先复用已有场景。必要时在预算内修正布局、局部景物或绘制范围；改变主要对象、空间关系、镜头类型或核心动态时，更新统一计划版本和原因，计算受影响的图层、镜头、证据及缓存并重新检查。技术重试继续遵守原冻结计划，不借重试暗中改题或扩大预算。

同片复用不覆盖已有创作继承规则。从零重做使用本次目标建立新世界，不经公共场景缓存回填旧源码、旧布局或专用方法；技术重试则保留原有有效世界和镜头计划。两者不能因采用相同空间描述而混为一条路径。

Canvas 可缓存透明绘画平面，在合成阶段施加镜头变换；SVG/HTML 使用自身允许的组、变换和遮罩；Three.js 使用几何、分组及相机。不得为了共用设计越过当前后端的实际能力或准入限制。缓存按预计视域和最大放大需要分配，限制像素数、图层数、临时空间和生命周期；分辨率翻倍意味着像素缓存内存约增至四倍，不承诺任意超大画布或 60 fps。

镜头、视差、雾、水、粒子等以绝对帧号、任务 fps 和固定种子求值。相同帧在顺序播放、跳转和重复求值时一致；不依赖墙钟、`requestAnimationFrame` 或逐帧累加状态。作品风格可以变化，但不能以缓存、重放或分段边界为由无意改变对象位置与表现。

## 四、图片学习、视频学习、效果库共用渐进学习流程

各入口共用对象、区域、深度、分层、遮挡、镜头和局部动画的描述语言，但保留不同来源的证据能力。图片学习、视频学习和效果库的独立入口、项目与历史继续保留，不因共同设计合并库或导航。学习关注可观察的组织方法与适用条件，不强迫所有题材使用山水对象、同一网格、固定图层或固定动画。

| 阶段 | 学习目标与产物 | 可以声明什么 |
| --- | --- | --- |
| 1. 来源与观察 | 冻结输入、来源和实际读取范围，记录可观察的对象、构图、重叠、墨色或材质线索 | 只声明实际查看到的内容；未读取、排除与未知项可见 |
| 2. 空间与分层假设 | 提出锚点、区域、尺度、逻辑深度、依附、遮挡和分层模型，标注依据、替代解释和置信度 | 单图可支持空间关系假设，不证明隐藏结构、真实距离或镜头运动 |
| 3. 有界构造验证 | 用当前已准入后端制作布局或静态小样，检查锚点、比例、遮挡、层次与来源目标 | 区分原图观察、重建假设和小样实测；生成出图不代表学习正确 |
| 4. 时间与运动学习 | 对具备时间证据的视频分析镜头运动、视差、物体运动、局部动态和剪辑；生成有界复现短片 | 静态抽帧合同仍只提供推断；实际运动结论绑定所观察的时间范围 |
| 5. 新内容迁移 | 使用已提炼的方法完成不同内容的独立练习，遵守迁移阶段的原参考与复现基线隔离 | 复现通过不等于方法已可泛化，迁移仍需独立验证 |
| 6. 比较、修正与沉淀 | 比较参考与实际输出，保留失败、有效方法、局限和未完成项，形成可追溯的方法记录 | 静态、时序重放、连续视觉观察、音频和艺术评价分别记载，不合并为“全部掌握” |

阶段依据目标和输入证据选择，不能把完成全部阶段作为每张图片的强制高成本模板。图片可以完成空间与静态分层学习，再选择做派生动画练习；后者的镜头是创作结果，不是从原图观察到的事实。视频也可以先完成抽帧结构学习，再在明确预算内升级到时间证据；不具备升级能力时保留待学习状态与原因。迁移阶段沿用已有隔离规则，不携带原参考素材或复现基线源码；提炼方法在不同内容上的有效性单独记载，不因复现成功而升级为已验证迁移能力。

### 图片学习

学习主次关系、对象锚点、占位、尺度、留白、地面或水面接触、轮廓与遮挡、虚实和风格相关层次。单图中的前后关系可能有多种解释，不能从对象在画面上的上下位置直接导出真实深度。对不可见部分、精确三维结构、相机路径与运动均允许未知。

布局草图、网格图或分层假设应与真实像素观察绑定，供后续小样验证。自动修正可以针对漂浮枝叶、错误比例、硬山脚切口等问题，但不能用强行变黑、统一模糊、整体洗淡代替目标风格的构图和笔触判断。

### 视频学习

来源证据区分：静态抽帧、具有顺序与真实时间戳的帧序列、实际观察的有界片段、完整视频连续观察。沿用现有请求时间、实际 PTS、time base 和重复帧映射；证据结构保留源媒体身份、选段、时间戳和采样规则，同一解码帧重复命中不增加实际观察数量。可变帧率和非零起点不得仅用帧序号猜测时间。按需新增观察仍受本次冻结来源范围与剩余预算约束。未观察音频时，音频结论保持未知或未观察。

逐步学习固定机位与物体运动、平移与推拉、景层视差、局部雾水或粒子动态、转场与剪辑。区分画面坐标变化来自相机、对象、图层变形、数字裁切或剪辑的不同假设；例如单目视频的推近与数字变焦可能不能唯一识别，不伪造标定的三维轨迹。镜头静止但对象活动，以及镜头与局部动态同时变化，都应是可学习情形。

运动复现用绝对时钟和固定种子验证，保留真实输出与相应连续片段的观察证据。时间稳定性通过不能代替观感、节奏或艺术判断；一段片段通过不能扩大成全片已看完。旧 `sampled_frames_only` v1 的输入和结果语义保持不变；真实时间观察需要版本化合同、能力准入及相应测试后才可启用。

复现阶段以本次冻结的参考目标、动作与节奏要求为准。自动编排不能为了复用或成本把应复现的镜头运动换成固定机位，或添加参考没有的动态后仍宣称复现成功；独立迁移或自主创作则由其新目标决定动静组合。

### 效果库与 WikiSkill

效果库既有候选、源码、样片、方法、评价和反馈可共用上述空间及时间学习记录。方法应能表达对象与分层组织、镜头或局部动态配方、参数范围、依赖、实测证据和局限；这些是方法与创作指导，不是本轮新增的跨影片可执行场景资产库。

效果采用、候选内部最佳、学习阶段完成和 WikiSkill 发布保持独立。好的效果按既有精选流程留存；失败、撤回和不确定性也可作为反例保留。WikiSkill 沿用用户显式发起的整库快照、编译、校验和发布；图片学习、视频学习、出图或影片完成不会自动发布或替换代表效果。

新发布可提炼有证据支持的空间、分层、遮挡、镜头和局部动态方法，附适用风格、来源及验证范围，并交代覆盖与排除。正式批次冻结确切发布版本，按需检索和读取；跨任务传播的是方法、代码指导与适用条件，不自动把旧影片的山、树或活场景对象装入新任务。读取知识不授予新执行能力，关闭 WikiSkill 的既有行为和历史发布均保持原义。

## 五、自动质量门控、预算与受控修订

技术与空间硬检查关注对象身份、锚点和依附、尺度、遮挡、出界、最大推进的清晰度、层间接合、时间稳定性、镜头连续与执行区间连续。视觉评审关注本次目标的构图、虚实、层次、材质、笔触和节奏；按风格判断，不能把留白多、远景淡或静态镜头本身判成缺陷。视觉意见保留不确定性，不把数值通过写成艺术认可。

先做有代表性的低成本布局、关键帧和短预览，覆盖实际镜头的推进极限、边界、遮挡及主要动态，再决定是否完整导出。预演只支持其真实观察范围；导出后的完整解码、时间与音频验证仍独立存在。预演不能被标成已经完成长片，也不要求新增用户逐镜头编辑或确认流程。前置学习、预演和修正受既有任务、子任务与次数限制约束；不自动新增成片后评审或修订轮次，不通过派生子任务、重试或新计划版本重置预算与累计谱系。

模型生成、自动评审、协作、局部修正共用任务的模型预算；绘画、预览、缓存和最终导出使用独立记录的资源与时间预算。宿主冻结平台上限及用户更紧限制，规划器可在剩余额度内分配，不能暗中提高上限、遗漏失败成本或把历史复用请求记成新生成。实际 token、调用、时间和峰值资源按可取得的真实用量记录，未知项保持未知。

预算耗尽仍未达标时停止正式输出，保留最佳预览、缺陷、已用预算、未完成项与可重放的计划版本。恢复同一技术失败继续验证原计划和有效成果；改变方向属于明确的新计划或新任务，保留旧证据和既有重试边界。

## 六、接入边界与实施顺序

1. 定义有界、版本化的共同空间与时间描述，以及来源观察、推断、复现结果的区分；历史缺失字段不填成已验证能力。
2. 在统一规划与制作中接入世界、镜头、执行区间引用、对象级布局、风格规则和预算，建立计划变更的依赖与失效关系。
3. 首先以一个 Canvas 场景和多个全自动镜头验证空间与合成；SVG/HTML、Three.js 验证共同语义与各自能力边界，不要求像素一致。
4. 将图片学习接入空间和分层假设、静态小样比较；将视频学习区分旧抽帧路径与新增时间证据路径，逐步验证镜头、视差及局部动态。
5. 将相同记录用于效果方法、反馈及整库 WikiSkill 快照，保持精选、发布、批次冻结和执行准入的既有边界。
6. 有实际验证后，再评估镜像准入、部署和真实作品验收。若届时需要构建镜像，继续使用 `latest` 标签，以摘要和标签记录身份。本轮不执行这些动作。

## 七、后续验收矩阵

| 范围 | 必须覆盖的情形 |
| --- | --- |
| 共同空间 | 同一对象跨镜头/区间身份不变；图层正确遮挡；树根落地、叶依枝、船在水面；错误比例和循环关系能被发现 |
| 风格与后端 | 水墨散点透视、平面 SVG 分组、Three.js 几何投影可表达同一上层关系；不越过当前后端能力 |
| 镜头与动态 | 固定镜头带局部动画、移动镜头带或不带局部动画、无动态画面均可由计划选择；无强制镜头模板 |
| 重放与资源 | 重复 seek、乱序帧、分段边界结果一致；极限推进无露边或失真；缓存可释放且资源有界 |
| 图片学习 | 单图前后假设保留不确定性；单图不能证明运动；派生动画明确标为生成练习 |
| 视频学习 | 旧抽帧 v1 仍拒绝运动观察声明；新时间证据覆盖静机位、相机运动、物体运动、视差与剪辑歧义；片段不冒充全片 |
| 渐进学习 | 已观察、已推断、已复现、已比较、排除与待学分别记录；失败与部分完成不会被写成已经掌握 |
| 独立迁移 | 新内容练习不接收原参考和复现基线源码；复现、迁移分别报告，不用成功复现推定泛化 |
| 自动修正 | 局部失败仅修受影响内容；重大修改更新统一计划并重验；不自由新增景物或覆盖历史证据 |
| 预算终止 | 评审/失败/协作消耗计入同一模型预算；资源预算独立；超预算不启动正式导出，最佳预览与原因仍可用 |
| 效果与知识 | 精选效果可保存学习记录；采用不等于知识发布；显式整库发布保留证据边界，新批次精确冻结，关闭知识与历史任务兼容 |

以上是待实施的验收要求，不是已经执行的测试记录。首轮以一个场景检验空间、分层、自动编排和成本，再逐步扩展到学习入口和其他后端；不以新增五分钟长片作为本次设计文档完成的证明。
