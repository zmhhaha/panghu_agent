## 正式制作

新无旁白制作可以选择场景路线：一次世界作者根据完整目标、风格与分镜意图，统一
确定少量世界、对象关系、镜头动静和覆盖范围，输出世界绘画源码及独立空间方法载体。
宿主按同一计划取景和复用对象缓存，执行区间切分不再要求重新生成山、树和背景。
初版固定主观看方向，允许平移、有限推进和对象局部变换/透明度轨道。

开始正式导出前最多生成三张实际 PNG，覆盖起点、最大推进、终点，以及每个世界
首次出现的位置；这些位置可以重合。所需集合超过三张时，在绘画前拒绝并保留
源码和计划，不省略某个世界后继续导出。
独立静态评审实际读取这些图像，核对目标、构图、层次、比例和可见问题；通过冻结的
分数及问题条件才继续导出。预演不达标、实际用量未知或预算耗尽时保留源码、图像、
评审和诊断。首版自动修复额度明确为零；不额外增加成片后的业务修订轮数。

世界作者复用现有静态作者的严格协议，以无参考、无基线的独立新内容模式工作。
镜头由宿主驱动，静态作者结果不会升级成来源视频的运动证据。知识使用保留确切
发布版本与关闭开关。旁白制作继续原有正式路线，原录音不会被新路线静默丢弃。
网页增加的是全片声音选择和只读预演，不提供逐镜头编辑或确认。

## 图片、视频学习与效果库

图片和视频学习在新实验冻结实际场景能力后，向作者提供
`video.scene-space-method.v1`：独立世界/计划、来源摘要与真实帧 ID、空间假设、
置信度、替代解释、未知项、一般原则和渐进学习阶段。源码仍为原严格文件集合。
世界假设可先输出几何诊断；执行计划选择新宿主后才产生实际像素。

单图保持静态证据，视频旧抽帧保持 `sampled_frames_only`。相机、对象、视差或剪辑
可以记录为有局限的假设，不能把它们写成已连续观察的运动、音频或精确三维结构。
本轮没有新增连续片段观察协议或音频观察准入。

换内容练习只接收提炼原则与局限，原世界、布局、来源媒体和复现基线被剥离。
服务分别保存原方法、生成练习、布局和实际渲染证据；模型不能自己将阶段标为已验证。
宿主渲染结果也不自动等于方法迁移成功或用户艺术认可。

效果作者用现有可扩展方法字段 `methods[].runtime_requirements.scene_space` 传递
新版本载体。宿主仅在新冻结能力下解释它，提取为与方法版本、作者输入和渲染操作
绑定的独立证据记录；可复用方法正文不携带本次场景实例。原作者结果完整保留，旧
方法正文和内容摘要不变。一个方法可关联多个场景或迁移记录。

`GET /api/method-lab/methods/{version_id}/scene-space` 只读这些记录。既有明确效果采用
和整库 WikiSkill 发布保持独立：留存、学习完成、浏览或出片均不会自动采用或发布。
用户发起整库发布时，快照才额外收集可见方法的空间证据；后续任务得到原则指导，
不会从公共缓存自动继承上一部影片的活对象。

## 持久化、版本和预算

`SceneSpaceStore` 按 owner/task 保存不可变计划历史、累计消费、事件幂等、活动预留
和预演。SQLite 事务阻止并发任务重复花费同一余额；修订失效旧预演，原版本仍可查。
有活动操作时不能另启技术重试。失败和超支保留真实记录，不通过新镜头或恢复清零。

正式世界作者尚无计划时，原生产 journal 先记录唯一付费意图、预算与实际回执；得到
有效计划后将作者消费纳入公共账本。学习库保留全实验的宿主渲染额度，跨轮次、迁移
和技术恢复累计；作者提交的更大计划额度不能扩大宿主实际时限。

正式预演每次最多预留 60 秒；预演和整片均扣除已有消费及其他活动预留，再以实际
剩余渲染额度和总任务 deadline 的较小值确定本次时限，不足 30 秒不启动渲染。

模型用量来自通用 Agent API 的 `job.usage`，请求数、输入/输出和缓存组件保留原义。
缺失或不完整计量保持未知，不推算成已知零或供应商收费。已知渲染余额仍可支持有限
诊断 PNG；未知用量不能授权后续模型评审或正式长片导出。

私有渲染队列在执行前保存唯一意图，GET 仅读取，后台 worker 推进。排队时固定实际
源码、计划和宿主请求身份；首次启动前核对固定版本，渲染器在写入自身执行 claim
之前再次核对期望请求摘要。已开始的操作只查原 claim 与停止证据，响应丢失不会
启动第二个容器。晚返回的查询也不能覆盖已经完成的结果或实际消费。
全片各次渲染携带首次冻结的能力 descriptor，服务升级不会自动重绑。读取停止证明
失败时保留独立诊断，执行继续处于未知状态，不把缺失证明当作停止或零消费。

容器内部宿主耗时与外层完整调用耗时分别标明范围；恢复缺失完整测量时保留未知。
对象缓存复用减少重复绘画与作者工作，捕获每帧和编码的成本仍然存在。当前测试不
支持宣称节省了某个固定 token 百分比或五分钟艺术质量已通过。

## 配置与验收

私有 executor 需现有隔离、HyperFrames、Canvas 准入，再显式启用
`--enable-scene-space-rendering`。它提供独立 `/api/scene-space-renders` 队列、能力读取、
幂等请求查询、媒体读取和取消；取消在实际停止前保持等待，不伪造清理证明。

正式服务使用 `VIDEO_SCENE_SPACE_PRODUCTION_ENABLED=1` 选择已准入的新能力。
作者与评审需要已有静态作者/评审 profile 的实际准入，可配置
`VIDEO_SCENE_SPACE_AUTHOR_URL`、`VIDEO_SCENE_SPACE_AUTHOR_TOKEN_FILE`；渲染使用
`VIDEO_SCENE_SPACE_RENDER_URL`、`VIDEO_SCENE_SPACE_RENDER_TOKEN_FILE`，或既有可信
method executor 的配置。凭据只由服务读取，不能由网页或源码选择。

新宿主实际执行准入限 Canvas 和静态绘画缓存。SVG/HTML、Three.js 的共同矩阵
适配器已实现并测试；它们尚未获得新宿主的像素执行准入。动态笔触重绘、连续来源
视频观察、旁白合成的新场景路线、部署及真实模型长片验收仍需独立实施和证据。

本轮原生验收使用真实 Chrome、Playwright、固定 HyperFrames、当前 ink-landscape
及 FFmpeg，覆盖相机推进、对象只绘制一次、局部遮罩、字体加载、重复/逆序/重新
加载像素一致性以及 H.264 全解码。真实水墨案例调用 `createStrokeGroupDocument`
及 `renderCanvas`，检查两笔产生的 3,833 个深色像素落在推进后的对象投影范围。
其零原点局部坐标约束见渲染适配文档，并已提供给制作、图片/视频学习和效果作者。
来源范围和摘要记录在
`evidence/scene-space-native-browser-20261122.json`。编排、预算、HTTP、旧合同和 UI
的集成测试与真实像素验收分别记录；测试夹具不充当模型或生产执行证明。

最终专项回归 **244 项通过，无跳过**，包含六个真实浏览器案例；制作 UI **21 项通过**。
另两项针对知识快照泄露和 HTTP 连接中断的复核均通过。完整结果范围见
`evidence/scene-space-stage2-validation-20261122.json`。

较早的广泛兼容检查为 1,100 项通过、20 项失败。将这 20 项放到未修改的阶段 1
提交复测，19 项同样失败，连接中断项通过；随后修复知识快照中的隐藏代表 ID 泄露，
该项与连接中断项复核均通过。剩余 18 项已知基线失败属于旧制作假网关与视频导入的
宿主身份测试，本轮未扩大修复，也未在最终修改后重跑整个广泛集合，不能报告全库全绿。
