# 从零重做、知识开关与恢复验证

本轮按已确认的[设计](fresh-rebuild-and-skill-loading-design.md)实现 OpenSpec T 节。此文区分代码测试、部署和实际创作效果，不把模拟媒体当成真实作品。

已接通网页及结构化 API 的新建、继续优化、同效果从零重做。fresh 只继承效果归属；当前目标、约束和有来源的问题摘要进入创作输入，旧源码、专用方法、资源配方和协作分工不作为起点。标准留空时由 Agent 先拟定再继续。新作品先作为候选，默认展示保持原作品，完成后以并发版本校验人工采用；采用与知识发布独立。

所有新创作默认加载 WikiSkill，可明确关闭。正式统筹固定开关与确切整库，模块、Manim、重启恢复和正片打磨继承。实验室读取同一发布库的完整冻结原文，并明确记录 inline 来源；它不冒称技能工具按需读取。关闭与启用但无发布版分开记录。平台规范始终提供；旧任务不改写身份与输入。

技术重试只提交原委托、新请求号和有限预算。完成的规划与创作检查点保留；有效视频校验实际文件与摘要后复用，失败渲染才重新执行。Manim 使用已停止资源和 recipe 检查点，保存原任务消耗、失败与停止证据。未知提交继续查原任务，不换 ID 猜测重跑。

验证包括前端入口与输入查看、OpenAPI、owner 与并发采用、普通／协作／Manim 输入、冻结知识与关闭路径、检查点恢复以及正式统筹到打磨的模拟链。各组有重叠，不能将其数量相加当成独立覆盖。最终测试和部署回执统一保留于 `D:/codex-work/operations/fresh-rebuild-20261117/`。
