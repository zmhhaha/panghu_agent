## 退步原因

线上项目 `2d86a0a73ae74c6ab95399cfb5e1d919` 的首次成功成图 `a71fde9ae8e849e0bf7f2466fbc6c6d1`，经恢复评审得到 44 分。与旧项目作品比较，山体主要依靠浅灰多边形和线性渐变，库笔触被作者逐笔设置为窄线，前景同样偏平涂；局部径向擦除留下山脚矩形边缘，松树来自相同的对称骨架。真实库调用与画质改善是两项不同结果。

原评审失败已恢复，后来项目失败发生在换内容阶段：候选 `e8e6d197175d43d7b31f0635fba7469a` 在 group 顶层提供 `ink/color/brush`，在 stroke 顶层提供 `path/width/opacity` 等未支持字段，真实库拒绝 `Unsupported stroke group field: ink`。迁移输入替换了原目标，因此嵌入原 goal 的长篇 API 说明不再存在；稳定运行时说明仅保留模块身份，作者开始猜测字段。

## 修复范围

`ink_landscape_library.runtime_guidance()` 增加中性接口契约，图片和视频的复现、评审及迁移都通过原有 constraints 路径取得它。契约包括合法 group/stroke 字段、极小数据结构示例、笔宽覆盖关系、六位颜色、数值型纸纹、透明离屏绘制、每文档容量与密度场边界。

接口契约不包含山形、树形、画面坐标或绘画技法。WikiSkill 开关仍决定是否取得知识正文；固定库源码修订 `bb7338a5c57d4151c3d8635a8549057bb0383ca0`、模块、许可和 manifest 摘要不变。

验证直接执行说明中的示例并用固定 ESM 拒绝原迁移错误字段，同时验证 512 笔边界和颜色/纸纹类型。图片和视频分别跑完整复现→迁移流程，在 WikiSkill 开关两种状态、原 goal 不携带 API 文档时验证相同运行时契约与知识读取边界。

三个完整相关测试文件共 **50 项通过**，181.58 秒。定向新增契约和知识开关检查已包含在该范围内，不重复累计。独立审阅逐项对照固定模块源码，未发现契约描述与当前版本不符。
