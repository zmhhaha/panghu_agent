# 动画创作知识工作台

开发者知识页位于 `/dev/animations/knowledge.html`。它用于查清一次实验实际发生了什么、Agent 从中形成了什么理解，以及哪些理解需要修正。打开页面、筛选目录、读取正文与历史版本都不会启动实验或调用模型。

## 三类内容的边界

| 内容 | 用途 | 修改与生效方式 |
| --- | --- | --- |
| 真实经验 | 保留实验失败、渲染结果、评价等原始记录，作为判断依据 | 正文不可改写；撤回评价后保留记录，并提示引用该证据的页面需要复核 |
| Wiki 知识页面 | 整理适用条件、局限、反例，以及经验之间的关系 | 可明确修正或停用；每次保存生成新版本，旧版正文可追溯 |
| 已发布 Skill | 给正式视频制作提供已经验收的创作方法 | 保持发布时的版本；修正 Wiki 不会直接替换正式制作使用的方法 |

Wiki 是持续积累的工作知识，后续实验可以读取冻结的知识快照。已经冻结的任务输入保持原样。新的方法仍需通过样片、迁移验证与开发者认可，走独立的发布流程才能成为正式 Skill。

## 日常使用

1. 从知识页面或实验经验目录选择记录；目录每类最多显示 64 条，也可按已知 ID 读取其他记录。
2. 查看完整正文、证据与历史版本。经验记录和历史版本只读；返回最新版本后才能修订页面。
3. 点击“修订当前页面”，核对正文、适用条件、局限、证据与状态，填写修正原因，再保存一个新版本。反例和关联页面默认保留，也可以在高级区域明确修改。

保存只维护知识，不表示样片通过验收，也不会发布 Skill。

## 冲突与未确认提交

保存采用 CAS：请求绑定编辑开始时读到的确切版本。若其他操作先更新了同一页面，服务会拒绝覆盖。界面保留草稿，要求先“重新读取最新版本”，再对照当前内容重新编辑与保存；不会自动重试或静默覆盖。

网络中断、服务暂时异常或回执不完整时，原提交可能已经生效。界面冻结原请求 ID 和正文，暂停新修订。可以“核对当前版本”，也可以明确“重送原请求”，后者发送完全相同的请求，由服务返回幂等结果。仅查询当前版本不能证明原请求是否完成。

未确认的请求与草稿只保留在当前页面内存中。处理完成前请保留页面；关闭或刷新浏览器会丢失这份本地状态。获得有效保存回执后，界面会重新读取最新页面，避免把旧的幂等回执误认为当前版本。
