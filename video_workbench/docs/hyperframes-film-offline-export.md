# 同一 HyperFrames 工程的离线完整导出

`hyperframes_film_export.export_film_browser_bundle()` 消费外部可信摘要绑定的浏览器工程包，独立重编译校验，复用 `mix_film_audio()` 生成完整原声交付轨，再由 `hyperframes_film_capture.mjs` 驱动同一根工程的全部全局帧。帧序列只编码一次，不拼接逐镜 MP4。它是独立离线入口，尚未接入正式制作编排、执行快照、Job 运输、新 Agent 产物合同或生产准入。

捕获覆盖 `[0, frame_count)`，再定位末帧、首帧和中间帧核对 PNG 字节一致。每帧验证实际核心时间、requested／completed frame、工程／film／模块身份、全局与局部上下文、真实绘制引擎观察、资源阻断和生命周期清理；不能用只有图像摘要的回执替代时钟证据。所有输入与自己的唯一临时子目录隔离，既有输出不覆盖；退出时删除自己的工作目录，子进程超时／取消先回收整个进程树。

最终输出为 H.264／AAC MP4，24fps、48kHz 双声道、零起点。MP4 movie timescale 使用 48000，以保留非整秒视频在音频采样网格上的确切终点；不使用 `atempo`、`-shortest` 或截断原旁白。成功前进行 ffprobe 帧数、时长和格式核对及完整音视频解码，并复核冻结输入、交付 WAV 和实际程序字节未变。回执绑定工程、bundle、全部帧、混音回执、工具与最终媒体摘要；返回的普通字典仍须在后续可信存储边界重新校验。

初版只接受最长 60 秒、偶数画幅、最多 512MiB PNG 和 128MiB MP4，最长执行预算 1200 秒。更长影片需要后续同工程分块捕获协议；这里不会静默裁片或回退旧拼接。统一音效事件暂未接入，明确 `sound_effects_mixed=false`。原输入工程的 `not_executed` 声明保持不变，实际执行另有回执；技术导出不授予开发者效果认可或 Skill 发布。

2026-11-14 本地检查：14 项 Python 通过，包括实际 FFmpeg 的 24／56 帧单次编码、混合采样率音轨、精确时长、持续到片尾的声音、错误帧／工程／上下文／迟到错误拒绝、输入不变、输出不覆盖、正常和失败清理，以及真实父子进程超时回收。该组使用合成 PNG 和捕获进程替身，证明编码及边界行为，不证明 HyperFrames 核心执行。Node 捕获边界检查另有 15 项通过、1 项 Windows 符号链接检查跳过，同样不作为真实核心证据。目标 ARM 环境的一次完整真实工程导出另行记录。

首次目标环境整片实测使用完整 Git `aa01950`，在 75 次核心定位和全帧校验之后，因编码音画时长不一致拒绝交付；失败及一次性执行记录保留，没有把它写成整片成功。随后独立的 `hyperframes-film-ffmpeg-diag-v1` 仅运行编码诊断，无浏览器／核心／模型：目标 FFmpeg 5.1.9 对 24／56／72 帧使用输出 `-frames:v` 时均提前结束音轨；去除该参数，改由已验证的有限 PNG 清单自然 EOF，三组音画时长分别严格为 1、7/3、3 秒，全部完整解码通过。本地 FFmpeg 7.1 未复现旧版行为。修复保留精确帧数与音频时长后置校验，时长不符时额外附实际 probe 元数据供失败归档，不改原声或使用宽松误差通过。
