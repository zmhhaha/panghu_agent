# 跨镜连续图解

本轮把连续图解接入工作台：使用各镜头已经采用的动态图解和录音，先整理跨镜对象关系，再审阅、采用并制作连续视频。它不改写原文稿，也不重新合成声音。

## 使用方法

1. 为至少两个镜头采用有效动态图解。制作草稿前，还需采用对应旁白和项目统一音色的录音。
2. 在「跨镜连续图解」中规划候选，逐边界查看对象关系。
3. 「延续同一对象」保留全局身份和外框，移动到下一镜布局；说明变化会单列，转场时渐变更新。「复制并保留原件」创建带来源的新对象，原件移到安全空槽。「不关联」让两段分别展开。
4. 修改关系后先保存为新候选。可以制作候选草稿；确认后明确采用。正式连续导出仍需采用该方案并逐镜人工核准录音时序。
5. 在「项目预览与成片」查看进度、播放、下载。普通逐镜制作入口与连续制作入口分别标识。

候选只建议相邻镜头中类型和名称精确一致、没有歧义的一对一对象；建议不等于已经确认其语义身份。用户必须审阅。说明可以在延续时更新，复制则要求完整内容一致；类型改变和模糊相似名称不会自动关联。当前界面可修改建议关系，暂不支持任意挑选异名对象建立关系。复制原件会在接收镜头中保留，不表示此后所有镜头永久常驻。没有关联的边界会明确显示，不能据此声称所有文稿已自动生成完整连续总谱。

## 实现和约束

- 独立 `video.continuity-plan.v1`、`motion-continuity-compiler-2`／`continuous-diagrams-2` 和 `video.render-snapshot.v3`。两张新增表保存不可变候选及独立采用头；采用只改变该头和项目版本。已发布的连续compiler1仍按原字节重建历史快照，新制作默认使用compiler2。
- 稳定实体、复制来源、前后边界状态、时间轴和编译文件摘要全部冻结。后一镜初始状态继承前一镜最后实际编码帧；每个后续镜头增加0.6秒转场，完整原录音随后播放。
- 保持逐镜Kubernetes Job、60秒时长、8MiB音频、执行预算和归属清理限制；转场占用该时长预算。复制无安全空槽、源对象已隐藏或移动会互相穿越时明确拒绝。
- 候选绑定镜头顺序、视觉语义和已采用图解版本。图解变化会使方案过期；更换有效录音后重新绑定时间轴，不自动重做画面，也不自动核准时序。
- 原compiler1至5及历史snapshot继续保持原身份。没有修改共享Agent合同、运行池或其部署。
- 确定性SVG/HTML与GSAP动画，720p／24fps；未引入生成图片、背景音乐或新语音模型。
