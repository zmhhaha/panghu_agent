# 场景制作的导出前预演与有限修正

日期：2026-11-25。对应映射 OpenSpec 项目中的
`add-scene-space-layer-camera-learning` 3.4、3.5；本次是实施进度，不代表这些任务全部验收。

## 执行路径

新创建的场景制作冻结 `pre_export_gate_revision=2`。整片一次规划/绘制之后，依次执行：

1. 校验共同世界、空间关系、全镜头边界和缓存预算，并保存有明确范围的布局报告。
2. 渲染最多三张关键画面，覆盖开始、实际最大倍率、结尾及每个世界的首次出现。预算容不下必须覆盖的世界时明确停止。
3. 用同一个源、冻结计划及原绝对帧时钟渲染最多两个短片窗口，每个最多 48 帧。根据声明的镜头/局部轨道变化和镜头边界确定性选窗，固定镜头同样有效。
4. 验证短片技术结果、原始媒体摘要和真实首尾抽帧，再把静态画面与短片抽帧交给独立静态评审，最多七张。评审图片运输回执必须覆盖实际图像摘要。
5. 评审达标且无问题才允许整片导出。否则，在预算允许、评审未建议停止时，最多执行一次同内容源码修正，重新预演和评审。

旧任务沿用各自已冻结的 v1 策略，恢复时不添加新短片或额外修正。新策略不改变旧的输入/世界/计划协议、固定渲染器及历史执行身份。

## 修正范围与保留结果

本轮自动修正只修绘制源码。原目标、风格、世界/对象、布局、镜头、局部动画、时长、预算及 WikiSkill 快照保持固定；返回的计划必须等于原计划，文件必须确实有变化。需要改变对象位置、空间关系或镜头的缺陷仍应通过既有可追溯计划修订处理，当前不会偷偷重新规划。

修正使用同一次制作的实际输出图和精确源码约束，不创建学习迁移实验，不加载原参考，不借旧复现作为新内容的基线。保留修正前的源码、关键帧、短片、评审及运输证据。页面可查看当前短片及修正前画面；最高抽样评分对应的预演索引仅用于找回已有结果，不等于用户认可。

所有提交都先持久化操作意图。未知提交只查询原操作；取消必须等远端停止证明。已停止但成本未知的原短片仍可取回，后续新工作受预算限制。已结算事件不改写为另一结果；预留后、派发意图写入前中断留下的已知未派发预留按零实际成本释放。

## 预算与证据范围

模型和渲染预算分开。首轮作者在尚无有效计划时先在制作日志保留有限准入预留及实际成本，计划验证成功后按原操作 ID 结转到累计账本。失败/无效作者结果的成本仍保留在制作日志中。后续评审、修正、预演和整片导出均有预留及实际结算；修正不重置成本。

模型预留同时需要正请求数和有限正 token。新策略按当前 picture profile 最多八个上游请求的硬上界预留调用数；token 准入额度最多 262144 且不超过当前剩余额度。实际请求数与 input/output token 按服务端用量结算，缓存输入不重复收费。未知用量不填零，超额照实保留并阻止后续导出；活动模型预留和正式导出互斥，已结算 ID 不能再次派发。

**限制：262144 是业务层准入预留，不是上游 input+output 总 token 硬上限。** 当前网关没有每作业总 token 强制停止合同。原生请求输出上限及八次请求上限不能证明总 token 不超额。因此 3.5 的硬总额度闭环仍待实现，不能仅凭本次测试标成完成。

布局报告只检查声明几何和 bounds，不声称检查了实际绘制像素的遮挡。短片是实际渲染的有界视频，独立评审仍只收到抽样静帧；不声称连续运动/声音已被模型观看，也不把评分当作用户审美验收。技术宿主的重复、逆序、重新加载检查不等于所有帧的艺术与时间质量验收。

## 发布边界

默认开关 `VIDEO_SCENE_SPACE_PRODUCTION_ENABLED=0` 保持关闭。本次源码及本地测试不表示已部署或已经放开正式场景制作。水墨成片/五分钟影片验收继续暂缓；既有标准制作路径不改。没有接入 video-shotcraft 的代码、运行时或资产，也未自动发布 WikiSkill。

验证覆盖纯布局/选窗、真实短窗浏览器渲染与编码、私有抽帧运输、预算并发、旧任务恢复、有限修正、失败/未知提交及取消。合成运输测试只验证状态机与证据保管，不作为作品效果达标证明。完整发布和真实制作闭环仍由 OpenSpec 6.2–6.4 跟踪。
