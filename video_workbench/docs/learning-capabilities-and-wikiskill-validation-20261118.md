## 已实现的执行边界

图片和视频学习仍由观察实际参考的作者生成完整可编辑源码，分别通过 HyperFrames 输出单帧或完整 MP4。第一次复现创作可以直接交付，也可以按需提出至多两个内部技法小样和/或两至三个职责部件。小样必须真实渲染并独立评审；部件取得直接依赖源码和小样证据，再由作者整合完整作品。当前按 DAG 顺序调度，`max_parallel=1`，没有宣称部件并行。

这些角色共享同一冻结目标、反馈、知识选择、能力准入和截止时间。小样单列在实验历史证据中，不变成效果库作品；复现和一次换内容验证仍分别保留。明确关闭小样或协作后，提出相应计划会被拒绝。技术重试保留原计划和已付费源码，只恢复确切未完成阶段；已完成任务的旧输入不能被错记为下一个部件。静态帧与视频采样帧仍不构成连续观看、音频听审或用户认可。

Manim 是与其他绘画能力并列的创作选择，通过共用 recipe/Cairo 生产者制作真实资源。先观察参考，再提出几何和材质目标，完成资源后再编排画面；recipe 角色接收观察作者的说明，不能声称自身看过参考。图片输出使用本地零帧已完成的一帧透明资源，并保留 Python；视频资源维持当前 24 fps、最多 60 帧及解码像素预算，不把这个上限误写为整段 60 秒 Manim。只有 Manim 被选择时不能用 HTML 几何替代；当前 Manim 资源路线不和内部小样、职责部件同时使用。

每个新的复现轮次和迁移作品具有独立资源身份。继续创作可以参考较好作品的真实 Python；从零重做不继承实验前源码，但可以在本实验后续轮次使用自己已经生成的作品。技术重试可复用已完成、已停止的资源，不重付 recipe。资源放置使用局部时间和全局半开区间，实际消费、摘要和停止证据分别验证。

开发者可从一个已渲染图片版本点击“用此版本创作动画”，创建关联的需求创作作品。原图片项目、版本和艺术结论不变；新动作独立创作和验证。结构化 API 为 `POST /api/picture-lab/projects/{id}/animations`，相同请求键恢复同一委托，不能通过公共 JSON 伪造来源。Manim 图片的 Python 作为创作参考保留，重新规划动画资源，旧单帧 PNG 不作为新动画的运行依赖。

网页与 JSON API 提供相同能力选择和策略开关，按实际运行准入显示可用选项。图片当前不要求动作编排；视频提供已准入编排能力，纯 Manim 自动停用浏览器动作选项。学习渲染器尚未准入的 Anime.js 不因需求创作库已支持而自动开放。
