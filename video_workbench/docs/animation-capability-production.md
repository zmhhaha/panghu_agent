# 动画实验成果进入正式制作

2026-11-08 至 2026-11-09；开发分支 `codex/video-capability-experiment-redesign`。

## 要解决的问题

本轮开始前，实验室已经可以让通用 Agent 编写可定位时间的 HTML/SVG 动画，正式工作台仍只接受受限 motion/process JSON，再交固定编译器生成画面。实验指导语和自由动作当时无法越过这个边界，只复制 prompt 不足以解决问题。

本轮补齐“实验反馈 → 发布能力策略 → 真实旁白与文稿 → 生成源码候选 → 隔离渲染预览 → 明确采用 → 冻结整片导出”。普通用户不需要操作实验页、选择引擎或管理策略版本。

## 开发者：让实验成果进入正式制作

实验页的标注是改进依据，不会直接改变正式生成。可复用的结论需要整理成“能力策略发布包”：一组有明确适用范围、证据和版本的创作规则。实验室与正式制作共用 `video_workbench/animation_capabilities.py` 中的注册表，当前首包为 `explanatory-motion-v1`。

1. **从反馈提炼规则。** 将“4.6 秒转弯时不好追踪”转成可检验的表达要求，例如对象与标签一起移动、转向保持连续、片尾留出可读的稳定状态。保留原作品、时间区间和评价来源；一次样例的评价不能证明所有动画都改善。
2. **新增不可变发布 ID。** 在注册表新增唯一 ID，例如后续的 `explanatory-motion-v2`，保留旧包。`targets` 写适用问题，`engines` 写准入引擎，`rules` 写完整规则；`evidence` 记录来源、结论适用范围和来源文件的 SHA-256，`limitations` 写未验证范围。SHA-256 是内容指纹，用来核对实际使用的完整包。改规则、范围或证据都要另建 ID，不能覆盖原 ID，也不能把客户端改写的包当成已发布策略。
3. **用同一包开新实验。** 使用包含该包的实验执行器，显式冻结发布 ID：

   ```bash
   python -m video_workbench.animation_experiment_runner init --directory <新实验目录> --capability-release <发布ID>
   ```

   初始化只准备实验，不启动模型。后续按实验执行流程运行、比较与标注，核对冻结输入中的完整发布包和内容指纹。局部指导语仍单独保存；它不会自动成为生产规则。测试后需要改规则就再建发布 ID、开新实验，不重置旧实验槽位。复测结果记录在对应作品和推广回执中，不回写已经冻结的包。
4. **审查后发布默认策略。** 确认适用目标、复测效果和限制后，将 `DEFAULT_RELEASE_ID` 指向通过审查的包，同时保证注册表中旧包的键、包内 ID 和内容原样保留，发布包含同一注册表的实验端与正式业务服务。正式路由启用后，用户新建“创意动画”候选自动读取默认包；用户无需选择版本或操作实验室。仅修改实验标注或服务器临时 prompt，不会完成这一步。
5. **核对真实制作。** 用真实文稿和已采用录音生成新候选，检查候选绑定的发布 ID、内容指纹、预览和整片结果。新默认策略只作用于新任务；历史候选、实验、录音和已冻结成片仍使用原输入，不会被后台替换。想比较优化效果，需要明确生成新候选并与原版本比较。

## 用户：在正式工作台使用

普通用户继续在视频工作台操作：

1. 整理文稿、镜头旁白与画面重点，保存当前内容。
2. 选好项目统一音色，生成或上传真实配音，试听后点击“采用此配音”。创意动画使用这条录音的实测时长和讲解节点安排动作。
3. 在镜头的“画面制作方式”选择“创意动画”，提交生成候选。生成只保存候选，不自动采用，也不改变已采用画面。
4. 制作并观看该候选的 MP4 预览，检查表达、布局、运动与声音是否一致，再明确采用满意的版本。源码在独立渲染环境运行，工作台展示渲染后的视频。
5. 结合实际配音逐段核对画面时序，再确认“人工核对”。创意动画不能直接改写已生成源码的讲解节点时间；需要调整动作节拍时，请在动画要求中提出修改并生成新候选。生成成功或采用画面都不等于时序已核准。
6. 用已采用版本制作整片 MP4 草稿，检查整体节奏；各镜头补齐必要确认后，再正式导出。

旁白或采用录音变化后，旧创意候选可能已不匹配，需要重新生成；系统不会通过拉伸动画或截断配音掩盖差异。历史媒体仍保留用于对比。

## 制作边界与实现

复用通用 Agent 已有 `video.animation-experiment.v1` 创作协议，不改写冻结 v1 profile 或引入另一套长期 Agent 服务。业务适配器显式输入场景语义、旁白、当前采用录音的摘要和实测时长、beat 时间与已发布策略。产物是可执行源码，必须按不可信代码处理，不能嵌入已登录的工作台网页运行。

源码候选与既有通用图解、过程演示共用项目归属、操作、取消、候选、采用和时序审阅机制。镜头前后留白保持源码起始或末尾状态，不改变录音与源码内部节拍。普通整片草稿与导出可组合源码镜头和旧编译镜头，冻结源文件、音频、策略、创作输入、渲染适配器与运行资源；既有 v2/v3 快照含义保留。

**新 HTML/SVG 创意动画不能与既有固定“跨镜连续图解”方案混用。** 创意镜头走普通整片草稿和导出；既有连续方案仍走原连续制作入口。首版没有把自由源码纳入固定跨镜对象衔接合同，也不能据此宣称任意创意镜头之间已实现连续运动。

首版正式准入 HTML/SVG。Canvas/Three 的自由生成需要各自执行与观察验证后再启用，不因实验组件可播放就自动扩大生产准入。源码镜头采用绝对时间 seek、隔离 Chromium 截帧和 FFmpeg 编码；旧编译动画继续 Hyperframes。两条路径复用同一内部 K8s 执行、无凭据/无外网边界、原声合成、输出验证及取消恢复。技术检查证明源码可执行与时间可复现，不自动证明画面审美或内容正确。

## 验收与依赖

验证策略输入绑定、过期拒绝、归属隔离、候选采用、历史复验、音频完整、反向定位、混合整片导出和浏览器操作。使用真实文稿与录音的新任务验证，单独记录模型调用次数与失败，不重用或重置上一轮四个已结束的实验槽。

旧的 drain 发布方法要求先清空全局执行槽，因此会被尚未取得停止证明的历史隔离任务阻塞。这是该发布方法的局限，不应理解为新能力只能等旧任务全部恢复后才能登记。新的 additive admission（增量准入）路径允许保留旧配置和任务记录，单独增加并验证新能力；历史 quarantine（停止状态仍待核定的隔离任务）、配额和停止证明要求继续保留，不清空记录或伪造回执。

增量准入不代表框架 P3 恢复问题已修复；该问题仍归属 `harden-shared-platform-production-readiness`。代码接入、隔离验收、共享路由启用、线上可用分别记录，以实际回执为准。公共渲染服务拆分、框架计费与存储回收不纳入本次业务任务。
