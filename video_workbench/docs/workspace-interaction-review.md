# 视频工作台交互梳理与建议

2026-11-13。用户反馈线上没有删除项目的入口，希望参考Premiere等视频制作软件改善交互。本轮实施项目回收站；本文件其余布局、时间线、批注和制作版本整合均为待讨论建议，不代表已经实现或获准改动主流程。

## 实际页面问题

浏览器检查的专用三段项目已生成29秒整片有声草稿，但页面同时保留新整片策划和制作、旧项目导出、按镜头批次、旧连续图解、单镜动画及配音入口。当前展开状态页面高7074像素，浏览器视口高720像素。用户需要反复滚动，难以辨认主流程、当前版本和下一步操作。

新整片制作使用准确音画候选，不写用户逐镜采用指针。该隔离是正确行为，但分镜卡片只看采用指针，仍显示“动态图解待制作／未采用配音”，与整片已完成的事实容易混淆。同一个项目上方还显示方案预计47秒、已采用配音0秒，而整片实际29秒放在另一处。建议按所选整片版本展示状态与实测时长，人工采用和核准单独标记，不通过自动采用掩盖显示问题。

当前“文稿版本”来自项目整体revision，生成结果、留白或音色变化也会推进，并非独立稿件版本。整片制作历史、渲染历史、音频版本与动画版本散在多个面板，缺少统一的“当前正在看什么”。整片草稿状态还重复显示“草稿待审阅”。这些问题优先于配色和工具栏数量。

## 推荐的工作区

借鉴视频剪辑软件的区域分工，保留Agent负责创作与修改的方式：

- 顶部：项目名、当前制作版本、方案／制作／审阅三个阶段，以及当前阶段一个主操作。
- 左侧：项目库、项目更多操作与回收站；进入项目后可查看段落列表。
- 中央：一个主要播放器，显示所选整片草稿或成片；版本、音色、实测总时长与播放／下载在附近。
- 右侧：所选段落的旁白、表达目标与状态；切到修改意见时按当前版本和时间位置提需求；项目音色留在项目级设置。
- 底部：按冻结成片实测边界绘制的段落时间线，点击跳转，播放时高亮；初版用于理解结构、定位和标记问题。

手机端改为预览、段落、意见的标签切换，不把桌面四区缩成小字。Canvas、Three.js、源码和Agent日志留在详情，不要求普通用户选底层渲染参数。

## 分期建议与依赖

| 顺序 | 调整 | 能复用的能力及缺口 |
| --- | --- | --- |
| 本轮补缺 | 删除项目、回收站和恢复 | 新项目生命周期状态及接口；运行中／未知任务拒绝删除，不主动取消或物理回收资产 |
| 第一轮 | 整合整片播放器、历史与分镜状态；收拢旧入口 | 整片run、准确候选和媒体路由已有；需让UI以所选整片版本投影状态，区分未采用与未制作 |
| 第一轮 | 方案／制作／审阅三个阶段 | 复用现有策划、整体采用和制作接口；主要是前端重组及选中状态统一 |
| 第二轮 | 点击段落时间线、随播放高亮、上一段／下一段 | 播放器可seek；需提供冻结整片时间轴，含留白与实际编码边界，不能直接累加当前文稿的预计秒数 |
| 第二轮 | 右侧检查器与定位批注 | 旁白等字段已有；针对整片候选的版本／段落／区间意见，以及真正修改该整片的接口仍需补齐，不能用旧单镜按钮冒充 |
| 后续 | 制作前后对比、快捷键、面板尺寸调整 | 历史已有；对比需要绑定准确整片版本。快捷键应避开输入框并提供可见操作 |
| 后续 | 拖动换序、局部替换、多音轨显示 | 先完成既定跨段连续、独立审阅、正片轮次和需求账本；重排需要使旧依赖失效并检查邻段衔接 |

首个布局改版建议完成“统一状态与主播放器 → 收拢旧入口 → 可点击段落时间线”。不把多轨剪辑、关键帧编辑或特效参数堆栈列入首版，以免增加用户制作负担。整片的首次一轮打磨、用户主动追加最多两轮、后续明确需求列表仍按既定方案实施；实验室优化次数不受正片限制。

## 本轮交付边界

项目回收站独立实施和验收，删除只改变生命周期，不删除稿件、媒体和执行历史，不生成或采用任何新视频。恢复继续使用原项目身份与原有内容。平台存储回收不列为本业务任务。

可交互的布局提案保存在既有D盘证据目录的 `video-workbench-layout-proposal.html`，使用当前29秒三段结构说明定位和检查器关系。画面、批注、回收站交互仅为布局演示，不连接业务API，不表示批注或新版工作区已经上线。项目回收站实际上线与浏览器验收结果另记验证文档。
