更新：2026-11-03（Asia/Shanghai）。用户已决定全面转向动态视频。本轮应用源码为 `cbd08136ca0dc694ceeada3afdfdb55de65e62bf`，位于独立分支 `codex/video-hyperframes-motion`，尚未合入主线。**代码、本地测试、工作台发布、只读回归与隔离 API 验收已完成；本轮浏览器操作及整片人工效果核对仍待完成。**

## 用户现在将如何制作

新项目使用动态视频制作。保存总文稿后，安排分镜，可通过项目讲解方案统筹旁白、画面重点和展开步骤，再逐镜制作动态图解与配音。生成的内容先作为候选保存，由用户审阅和明确采用。估算时序可以制作视频草稿，正式动态成片仍要求结合实际录音人工核对时序。

本轮调整默认入口和页面组织，不把创建项目变成自动制作，也不颠倒现有文稿、分镜、讲解方案、画面与配音的制作流程。项目统一音色与八个音色选项保持，默认云健；动态图解继续使用既有 HyperFrames 生产链路。

## 已实现的行为

- 开启动态能力时，创建 API 省略 `production_mode` 也默认创建动态项目；前端新建入口明确采用动态模式。手动或自动新增分镜继承项目模式，尚无动态图解的镜头显示待制作，不伪造已采用候选。
- 动态图解作为主要制作区域；静态素材、格式及历史版本放入默认折叠的兼容区域，保留查看、下载、修订和显式复用能力。
- 项目预览与成片区域提供统一 MP4 操作入口。动态项目使用 v2 动态导出与校验；旧静态 timeline/render 不能绕过动态制作要求。视频草稿状态持续更新，动态模式隐藏旧字幕操作，默认关键点由画面表达并保留旁白。
- 旧项目需要显式选择转为动态制作。转换保留原文、镜头 ID、音色、已采用静态画面、动态图解、配音及历史；未制作镜头进入待制作的动态状态，已明确选择的静态镜头可以继续复用，新镜头继承动态模式。
- 转换要求当前项目修订号、所有者与 CSRF 校验；有画面、配音、动态图解、讲解方案或成片任务未完成时拒绝转换。前端同时保护未保存编辑和状态尚未确认的任务。
- 读取旧项目仅投影缺省值，不回写数据库。历史 MP4 下载、原静态项目和 ZIP 保持可用；项目转为动态后，既有成片仍可下载。

这是现有工作台的主流程切换，不是部署另一套工作台。静态能力仍支撑历史资料与混合镜头，暂不删除服务模块、数据库内容或历史媒体。
