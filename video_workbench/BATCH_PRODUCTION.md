# 整片批量制作

在同一项目内选择镜头，批量准备动态图解、配音和镜头 MP4 草稿，再集中审阅采用。每批最多 **12 个镜头**，项目统一使用已保存的一个音色。批次完成后，继续逐镜试听并核对时序，最后导出整片。

**操作顺序**

1. 保存分镜、项目音色、语速与读音设置、镜头留白。
2. 在「整片批量制作」中选择镜头，以及本次需要的动态图解、配音、镜头草稿步骤。
3. 点击「核对制作范围与任务上限」，查看三类任务分别最多执行多少次。预览范围只计算清单，尚未提交生成。项目内容或选择变化后，需要重新核对。
4. 勾选确认并点击「开始批量制作」。逐镜查看各步骤状态；生成结果保留为候选。
5. 在集中审阅区阅读图解、试听配音、播放对应草稿，明确勾选要采用的镜头，再统一确认采用。
6. 打开单镜制作区，结合实际配音调整时序，试听后分别确认人工核对。全部采用后，可点击「制作整片 MP4 草稿」检查连贯性；完成时序核对后，通过项目原有的「导出 MP4」交付正式成片。

批量制作期间，项目音色、语速与读音、镜头留白和镜头保存暂时锁定；试听、下载、查看结果和申请取消仍可使用。原有的单镜制作与校时入口继续保留。

**版本、时序与执行方式**

- 复用当前可用的图解、配音候选；镜头草稿还要求候选、时序、编译器和运行环境匹配。预览清单固定本次使用的确切候选，启动时校验项目版本和清单摘要。
- 批量协调器在所有项目与用户的批次之间串行安排子任务，一次最多一个在途子任务。逐镜按所选步骤制作，服务端持续维护进度。
- 子任务提交前先保存本地记录和稳定的幂等键。服务重启后查找原子任务并恢复进度，已经创建的任务继续使用原身份。
- 生成完成、采用候选、确认人工时序、正式导出是独立操作。批次完成不会自动采用，也不会自动确认时序或导出正式成片。
- 集中试听、草稿和采用始终绑定所列候选。采用前同时检查项目版本、图解和配音的当前采用版本；全部检查通过后，在一次事务中写入所选采用结果，任一冲突都会拒绝整笔操作。
- 整片草稿使用当前已采用的画面和配音，可混合明确复用的静态镜头，保留旁白且不附加字幕。草稿允许估算时序；正式动态成片要求逐镜完成实际配音的人工时序核对。

**失败补做与取消**

明确失败的步骤可手动勾选，然后点击「补做勾选步骤」。界面分别显示三类补做次数上限。补做建立新批次，严格处理勾选的失败步骤，保留已经成功的候选；后续步骤需要时，重新核对范围并复用已有结果另行制作。

「停止后续任务并申请取消」会阻止后续提交，并为本批次已经开始的任务申请取消。状态以服务端确认结果为准。提交或停止结果尚未确认时，批次保持暂停，批量协调器停止新增子任务；可重新读取原任务状态，等待服务确认。未确认步骤不能作为失败项重复提交。

**API**

写操作使用工作台登录身份与 `X-CSRF-Token`；创建批次和补做还需要 `Idempotency-Key`。所有项目、批次与候选均检查所属用户。

| 方法与路径 | 用途与主要参数 |
| --- | --- |
| `POST /api/projects/{id}/batches/preview` | 核对范围。传 `expected_revision`、`scene_ids`（1–12 个）、`steps`（`motion`、`audio`、`draft` 的非空子集）、`reuse_current: true`；返回 `plan_sha256`、逐步骤 `items` 与 `estimated_tasks`。 |
| `POST /api/projects/{id}/batches` | 明确启动。传相同范围和 `plan_sha256`，使用幂等键。 |
| `GET /api/projects/{id}/batches` | 读取项目批次列表，响应为 `{batches: [...]}`。 |
| `GET /api/batches/{id}` | 读取一个批次、逐镜步骤与汇总进度。 |
| `POST /api/batches/{id}/cancel` | 停止后续任务，并申请取消已开始的子任务。 |
| `POST /api/batches/{id}/retry` | 补做明确失败步骤。传 `expected_revision`、精确 `item_ids`，使用新的幂等键；返回带 `parent_batch_id` 的新批次。 |
| `POST /api/projects/{id}/batch-adopt` | 集中采用。传 `expected_revision` 和 `selections`；每项包含 `scene_id`、需要采用的 `motion_version_id`／`audio_version_id`，以及对应的 `expected_motion_head_version_id`／`expected_audio_head_version_id`。无旧采用时显式传 `null`。 |
| `POST /api/projects/{id}/motion-renders` | 既有视频制作入口。整片草稿传 `expected_revision`、`purpose: "draft"`、`subtitles: false`；正式成片使用 `purpose: "delivery"`。 |

批次终态为 `completed`、`partial_failed`、`cancelled`；`queued`、`running`、`blocked`、`cancelling` 仍需继续读取或处理。响应中的步骤记录保留确切的子任务、候选与草稿标识，草稿同时记录其图解和配音候选标识。
