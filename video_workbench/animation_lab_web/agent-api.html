直接提交动画需求，查询进度，下载候选视频和源码，再根据结果继续优化。此页和 API 沿用动画效果库现有的 OAuth 登录与开发者权限。

授权方式

凭据为用户安全提供的 OAuth 会话 Cookie 文件。部署 Cookie 名为 __Host-video_workbench；客户端使用 Netscape 格式的 cookies.txt，保留原域、路径、Secure 和过期信息。接入程序不读取或导出浏览器凭据。会话过期后由用户重新授权。

当前尚未实现独立的长期机器凭据，API 不支持 Bearer。每个 POST 必须同时包含：

  1. 有效的登录 Cookie，且会话用户具有现有开发者权限。
  2. Origin: https://video-service.panghuer.top
  3. X-Animation-Lab-Token: <catalog.csrf_token> 和 Content-Type: application/json

先 GET /catalog 取得当前 csrf_token。它是写请求防伪 token，不能替代登录 Cookie；服务重启后应重新读取。身份由 OAuth 入口确定。

提交与查询

以下为 POSIX shell 示例；Windows 可用 curl.exe 并使用本机 shell 换行语法。示例仅使用凭据文件名和 token 占位符。

curl --fail-with-body --cookie cookies.txt \
  https://video-service.panghuer.top/dev/animations/api/method-lab/catalog \
  --output catalog.json

检查返回的 availability.enabled；为 false 时当前制作执行器不可用，目录仍可读取。availability.allowed_engines、availability.motion_tools、availability.resource_authoring.manim.enabled 分别给出浏览器画面、动作编排与 Manim 的实际准入情况。从 JSON 取得当前 csrf_token。登录重定向或 HTML 表示需要检查授权。

1. 保存 request.json

{
  "request_id": "17c8a3ea-52b4-42d0-b875-f55ab241e2db",
  "title": "聚焦异常数据点",
  "goal": "制作一段数据点从整体分布中被选出并放大解释的动画。保留总体与局部的对应关系，文字清楚且不遮挡数据。",
  "duration_seconds": 18,
  "budget": {"max_rounds": 2, "max_seconds": 600},
  "criteria": [
    {"id": "focus", "description": "选中的数据点与总体分布之间的对应关系清楚。"},
    {"id": "labels", "description": "关键标签完整可读，且不遮挡主要图形。"}
  ]
}

request_id 是调用方提供的幂等键。固定 UUID 仅供示例，每个新任务都应生成新 UUID；超时人工重放保留原 ID。

字段约束
goal必填，非空文本，最长 16000 字符；title 可选，最长 500 字符。
duration_seconds默认 18，范围 1–60 秒，必须落在 24 fps 的整帧边界。
budgetmax_rounds 整数 1–8；max_seconds 整数 60–3600。
collaboration可选，新建实验显式开启，继续优化或技术重试可继承原协作配置。技术重试不重传此字段。先确认 availability.collaboration=true；对象中 max_components 为整数 2–4，同时要求 budget.max_rounds=1。普通制作省略此字段。
criteria可省略。提供时为 1–16 项，唯一的 id 与非空 description；可选 requires_motion、requires_audio 布尔值和 observation 文本。
capability_selection可选，分别选择 creation 画面创作与 motion 动作编排。默认省略，让 Agent 自选；组省略或空数组也表示该组自动。见下方能力规则。

标准的描述及 observation 最长 4000 字符。运动与音频标准需要对应的实际观察证据，静帧评审不能推断已经满足。

复杂效果：按职责分工创作（可选）

统筹先规划，部件分别创作，再整合为一条完整样片；无需调用方管理图层。当前支持 HTML/SVG、Canvas 2D 和 Three.js，具体以目录中的 availability.allowed_engines 和本次任务冻结的准入能力为准。画面创作与动作编排是两个维度；GSAP／Anime.js 等编排库仍需分别准入，并遵循绝对时钟规范。协作暂不与 Manim 预制资源或迁移任务合用。新建实验加入以下字段，并把本次探索轮数设为 1；继续优化或技术重试继承原配置，仍需设置本次预算为 1 轮。技术重试只传原委托、请求编号和预算，不重传协作配置：

"budget": {"max_rounds": 1, "max_seconds": 1800},
"collaboration": {"max_components": 3}

最多 max_components+2 个创作任务（统筹、部件与整合），另有 1 次完整样片渲染、1 次评审。实际规划可少于指定部件数；全部工作共用这次总时限，建议预留 30 分钟。未启用时请省略该字段，不能仅凭执行器可用就推断协作已开放。详情中的创作任务额度包含已预留任务，不代表模型请求数。

选择创作能力

能力是两个并列维度，可以搭配或组合。把下面的字段片段加入制作请求；无需让外部 Agent 操作网页表单。

{
  "capability_selection": {
    "creation": ["canvas", "three"],
    "motion": ["gsap", "animejs"]
  }
}
维度允许的值实际可用性
creation 画面创作html-svg、canvas、three、manim前三项检查 availability.allowed_engines；Manim 检查 availability.resource_authoring.manim.enabled=true。
motion 动作编排native-js、gsap、animejs检查 availability.motion_tools。历史样片标签或库名称不能证明当前准入。

每组单选约束使用该能力；多选允许 Agent 从所选集合中选择或组合，并非每项都必须使用。仅选 creation:["manim"] 时，动作由 Manim 自身编排，motion 必须省略或为空数组，非空值会被 API 拒绝，网页也会禁用浏览器动作选项。数组不能重复或包含未知名称。实际采用浏览器画面能力且动作组非空时，须实质使用至少一种所选工具，不能仅加载依赖，也不能使用未选的动作库；否则任务明确失败。原生 JavaScript、GSAP 与 Anime.js 都跟随同一 HyperFrames 绝对时钟。

Manim 与 SVG、Canvas、Three.js 同属画面创作，但先预制资源再加入样片。新请求的 capability_selection.creation 包含 manim 时，先由规划 Agent 决定实际采用的能力，宿主冻结决定后再继续；只有采用 Manim 才预占资源制作额度、调用 recipe Agent 并生成资源，未采用时不制作。仅选 manim 时，主几何和其变形必须来自真实 Manim 资源，HTML/SVG 只做辅助标记及构图。混选浏览器画面能力时，仍可选择浏览器动作工具；最后只采用 Manim 时，采用决定的 motion 为空，不强迫添加浏览器装饰动作。

capability_selection 是用户允许的范围，adopted_capabilities 是规划后宿主冻结的只读决定，规划前为 null。其中 creation、engine、uses_manim 是采用的画面方案，motion 是规划后仍适用的浏览器动作允许范围，并非每项都已采用；plan_operation_id、plan_result_sha256 关联规划结果。这些字段不能由请求方提交，也不等于实际样片的渲染证据。方法只有确实需要 Manim 才携带 producer 依赖。历史冻结请求及原幂等键重放保持原流程。

当 HTML/SVG 不在原画面选集且仅为 Manim 辅助承载时，creation 只列 manim，motion 为空；若原选集显式包含 html-svg 且规划采用 HTML/SVG 和 Manim，则同时列两项，浏览器动作约束仍适用。

选择 Manim 时，可省略 resource_authoring；规划采用 Manim 后使用默认资源参数：640×360、24 fps、从第 0 帧开始，默认 48 帧或不足 48 帧的视频总帧数。需要控制时，可传 {"kind":"manim","frame_count":48,"global_start_frame":0}。在新选集包含 Manim 的请求里，这是按需候选参数，本身不触发制作；没有提供或继承 capability_selection 而显式提供 resource_authoring 时，仍表示在主动画规划前预制真实资源。API 允许 1–60 帧，且资源不能超出整片时间线；网页表单限定 0.5–2.5 秒。非空画面选择不含 Manim 时不能同时传 Manim 资源。协作暂不支持 Manim。

详情的资源状态 awaiting_plan 表示等待规划，not_adopted 表示规划未采用 Manim、资源制作次数为零。两者均不代表资源或样片已完成。

这项选择只用于动画实验室及其 API。正式视频制作不增加能力选择表单，由 Agent 根据表达目标和已发布的 WikiSkill 按需选择。请求选择不等于实际使用证据，也不代表视觉质量已经认可。

状态与下载

状态 / 字段含义
queued / running已入队 / 执行中。
cancelling已请求取消，等待在途操作停止。
completed / failed / cancelled三种委托终态。完成也可能因为预算用完或停止进展。
stop_reasongoal_met、budget_exhausted、no_progress、developer_stopped、failed 或 cancelled。
summary / error结果说明 / 失败代码，可能为空。
best_candidate_id当前选中候选，可能为空。
candidates候选的 id、media_url、source_url、technical_status 等。
capability_selection本次公开的冻结选择，旧自动任务可能不返回此字段。它是创作约束，不能当成样片实际使用能力的标签。
adopted_capabilities规划后宿主冻结的只读采用决定，规划前为 null，旧任务可省略；不能当作渲染或质量证据。
collaboration可选的只读协作进度：stage、components 的标题与状态、completed/total 和 author_calls_used/author_calls_max。创作计数含已预留任务，不代表模型请求数。缺少计数不等于零，不把部件完成当作样片认可。

结合 stop_reason、remaining_issues 和候选结果判断完成质量。响应预算采用 creator、review、render、seconds 计数；与提交时的预算形状不同。

查看需求与逐轮 Agent 输入

表达目标不是完整 prompt。以下两个 GET 沿用现有登录与开发者权限，无需 CSRF，不启动、续跑任务或唤醒执行器。按需读取，避免加入详情的高频轮询；每个 UTF-8 JSON 响应上限 6 MiB。

GET /commissions/{commission_id}/prompt-inspection
GET /commissions/{commission_id}/operations/{operation_id}/input

第一个入口返回 submission、effective_request 和 operations 索引。submission.origin=captured_request、is_original=true 是新请求保存的原提交 JSON；历史数据为 reconstructed_frozen_fields、false，明确表示按冻结字段还原。有效需求另列默认值和继承后的实际冻结内容；两份文档都带 sha256。

操作索引包含 ID、阶段、状态、轮次及依据、输入摘要和 input_url。主规划轮次为 0，创作按实际顺序从 1 开始，评审关联对应候选；无法核实为 null。协作阶段另含 phase、component_id，仍遵守原有单轮合同。已有预占输入不表示模型已经执行或制作成功。

个别输入不能安全读取时，该项返回 available:false、input_url:null 和稳定原因码 unavailable_reason，其余可读项仍可查看；账本整体完整性异常则可能拒绝读取。effective_request 的预算是冻结执行计数，不可原样当成新制作请求。

第二个入口按需返回真实冻结的 input 与 input_sha256，可能包含需求、方法、约束、观察与知识快照。摘要针对 canonical JSON，不是下载文件排版后的字节；输入中的 URL 不会被递归重写。使用索引中的站点根相对 input_url 时，不要重复添加 /dev/animations。其他用户、已删除委托或跨委托的操作不可读取。

当前范围是主委托的规划、创作、评审及协作 Agent 输入。渲染和独立资源账本中的 Manim recipe 不在索引中。不提供运行凭据，也不猜测没有冻结证据的历史系统提示词；不能把目标文本或候选源码当成完整 prompt。

curl --fail-with-body --cookie cookies.txt \
  https://video-service.panghuer.top/dev/animations/api/method-lab/commissions/11111111-1111-4111-8111-111111111111/prompt-inspection \
  --output experiment-requirements.json

操作输入可按返回的 input_url 使用同样方式保存；操作 ID 应原样使用并进行路径段编码。网页也提供复制与 JSON 导出。

继续优化

仍用 POST /commissions，新建 request_id，传入基线和改进目标。保存为新的 JSON 文件，再使用前述提交命令。

{
  "request_id": "bb8c0924-41c1-4da1-b2b5-c0e038ca7741",
  "title": "改善聚焦后的标签间距",
  "goal": "延续总体到局部的聚焦结构，改善标签间距与画面留白。",
  "duration_seconds": 18,
  "budget": {"max_rounds": 1, "max_seconds": 300},
  "base_commission_id": "11111111-1111-4111-8111-111111111111",
  "base_candidate_id": "candidate-1",
  "feedback": "保留总体与选中点的对应关系，增大右侧标签间距，避免遮挡。"
}

基线必须存在且当前用户可访问。省略 base_candidate_id 时使用基线的 best_candidate_id；省略 criteria 时继承基线标准。新请求创建新委托，原委托保留。

继续优化省略 capability_selection 时继承原选择；显式提交时采用本次选择，提交 {"creation":[],"motion":[]} 可恢复自动选择。详情中的 resource_authoring 是只读进度，不能直接作为下一次请求的资源参数。

在同一效果下从零重做

提交 creation_mode:"fresh"、所属 effect_id、本次 goal 和预算；不提交旧的基线或方法。可附 problem_summary:[{"text":"已确认的问题","source":"developer"}]。旧源码、布局与分工不作为创作起点。标准可省略，由 Agent 拟定记录后继续，不等待第二次确认。新作品先作为候选，保留原卡片默认展示，之后由你明确采用。

新建、继续优化和从零重做统一默认 use_wikiskill:true；设为 false 可不加载动效知识，平台工具和 HyperFrames 规范仍提供。实际选择与版本固定保留在本次输入中，不会因线上发版在中途改变。

技术重试

只有原执行已确认停止才能技术重试。使用新请求编号，仅提交 {"request_id":"新UUID","retry_of_commission_id":"原委托ID","budget":{"max_rounds":1,"max_seconds":600}}。服务保留原需求、标准、知识与已完成方案，只修失败环节。要改方向、技术选择或知识开关，请另开继续优化或从零重做实验；不得把技术重试当重新策划。

默认重试保留原冻结运行环境。若首次普通画面渲染失败、Agent 已完成源码且原任务确认停止，可在上述请求显式增加 "renderer_rebind":"current-admitted"，并保持 max_rounds:1。服务在新冻结的已准入环境重新渲染同一源码，不再调用创作 Agent；原输入、Job、源码及账本均保留。此入口暂不支持协作、Manim 或已有候选，资产哈希和库版本必须兼容。同一请求编号重放不会切换到后来环境。可在输入查看的 renderer_rebind 与 render_replays 核对新旧环境及分开的作者、渲染输入哈希；不能自行提交或修改绑定收据。网页原有“重试”按钮仍使用默认语义。

采用默认展示作品

明确选择后调用 POST /commissions/{id}/adopt，提交 request_id、effect_id、candidate_id 和详情中的 representative_revision 作为 expected_revision。发生冲突须重新读取，不自动覆盖。采用只更新效果卡片，不发布 WikiSkill 或授予审美认可。

可附 reference: {"url":"https://example.com/reference.mp4","start_seconds":0,"end_seconds":8}。参考 URL 与片段时间只作为需求资料，链接不会自动读取或观看原片。请将关键视觉、节奏及目标效果写入 goal 或 feedback。

反馈与取消

POST /commissions/{id}/feedback 仅保存已授权的意见，不自动制作、选择候选或发布。以下 JSON 可存为 feedback.json：

{
  "request_id": "11b15293-1973-46a0-bd82-fba87e2d8c34",
  "kind": "comment",
  "candidate_id": "candidate-1",
  "comment": "右侧标签仍遮挡数据，请增加间距。",
  "start_seconds": 6,
  "end_seconds": 9,
  "region": {"x": 0.6, "y": 0.1, "width": 0.3, "height": 0.4}
}
curl --fail-with-body --cookie cookies.txt \
  -H 'Origin: https://video-service.panghuer.top' \
  -H 'X-Animation-Lab-Token: <catalog.csrf_token>' \
  -H 'Content-Type: application/json' \
  --data-binary @feedback.json \
  https://video-service.panghuer.top/dev/animations/api/method-lab/commissions/11111111-1111-4111-8111-111111111111/feedback

时间范围可省略；提供时必须成对，满足 0 ≤ start_seconds ≤ end_seconds ≤ 候选时长。区域可省略；四个值为 0–1 的归一化坐标，矩形必须位于画面内。

比较偏好使用 kind: "preference"、同委托内两个不同的 left_candidate_id / right_candidate_id 和 preference: "left" | "right" | "equal" | "neither"；comment 可选，不接受时间或区域。

POST /commissions/{id}/cancel 发送空 JSON {}，使用相同的写请求头。响应为 200，可能先进入 cancelling；继续查询直到终态。重复取消不会启动新任务。

发布和人类验收不属于本合同。Agent 只能按用户实际授权记录意见，不能代替用户声明认可。

客户端读取用户提供的 Netscape Cookie 文件，POST 前读取目录并设置 Origin / CSRF 头。catalog 输出隐藏 CSRF token；submit / feedback 文件必须显式包含 UUID request_id。

wait 的总超时与轮询间隔必须显式设置，超时只结束本地等待。客户端不自动重试写请求、不自动发布。成功 JSON 输出到 stdout，安全错误 JSON 输出到 stderr 并退出 1；命令成功后仍需检查业务 state。

download 可用 --kind source 下载源码；省略 --candidate-id 时使用当前最佳候选。输出文件必须尚不存在，完成后输出字节数与 SHA-256。

错误与幂等

API 错误通常为 {"error":"错误代码"}。OAuth 入口也可能先返回登录重定向或 HTML，应由用户重新授权。

HTTP处理
200 / 202读取、反馈、取消成功 / 制作请求已接受，随后检查状态。
400 / 422JSON 或参数无效，检查请求字段。
401 / 403 / 重定向检查会话、开发者权限、Origin 和 CSRF；不要循环重试。
404委托或候选不存在、不可见或已移入回收站。
409幂等键内容冲突、基线不可用或媒体校验冲突，读取当前状态后处理。
413 / 415请求过大（POST 上限 1 MiB）/ Content-Type 不是 application/json。
502 / 503 / 504服务不可用或网关失败，提交结果可能不明确。

同一用户以相同 request_id 和相同制作请求重放，返回已有委托；内容改变会得到 409 animation_method_commission_idempotency_conflict。反馈的幂等键也不能跨内容或委托复用，冲突代码为 animation_method_feedback_conflict。

POST 超时或连接断开后，先在 /catalog 中按原 request_id 查找，再 GET 详情；反馈可在详情列表中核对。结果仍不明确且人工决定重放时，使用原文件和原 ID。不要自动生成新 ID、自动重试写请求或追加轮次。
