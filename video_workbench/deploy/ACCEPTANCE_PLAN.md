# 工作台上线验收计划

日期：2026-10-29。工作继续留在 `codex/svg-video-workbench`，上线与真实验收完成后再请用户决定是否合入主线。

目标是让用户通过实际登录入口，把一份短文稿做成可修改、可明确采用、可导出的 SVG／HTML 素材。本文是执行清单，表内待办不表示已经通过。本次编写只读核对代码与现有记录，没有提交模型任务或修改线上服务。

## 开始付费前的准备

1. 固定一个已有运行基础的引擎和一个文本／工具调用模型，先不同时比较 Pi 与 Hermes。记录实际模型、provider、模型策略、资源包、工具环境、Worker 镜像 digest 和两个组合身份。模型、镜像或资源内容改变后，旧组合的结论不能直接沿用。
2. 完成工作台与所需 Agent 镜像的 `latest` 推送，保存本次真实仓库 digest。正式 Pod 必须能与该 digest 对上，本地 Image ID 不充当仓库发布回执。保留原 Agent 配置与已有科研任务绑定，不重建整个目录去覆盖现网已验收路由。
3. 从实际工作台 Pod，以专用 caller 只读请求 capabilities，确认 `video.storyboard.v1`、`video.scene.v1` 的 revision 均为字符串 `"1"`，各只有一个匹配项，且 `configured`、`ready`、`supports_inputs` 为 true。这里只做无模型连通检查。不可用时先修配置、scope、网络或池，不通过反复提交任务排障。
4. 使用两个实际登录用户检查入口：未登录不能读取业务内容；伪造用户头不能变成另一个身份；用户乙读取用户甲项目、源码和导出得到拒绝。核对代理实际清洗 `X-Forwarded-User`，从不受信任 Pod 不能直达工作台。登录入口、Agent 双向网络放行、PVC 和备份均需真实环境证据，已有禁网容器记录不能替代。
5. 为这一轮设定最多的任务尝试数与可接受费用，确认采集账目的方式，串行执行。沿用已经审定的调用限制；若要收紧限额，作用于视觉业务自己的组合／调用方，不影响科研任务。失败或提交不确定时先取证，不自动创建第二次付费尝试。

正式视觉路由尚无验收时，先按下一节完成候选取证，再启用路由并执行 capabilities 检查。入口和数据准备可以同时进行。

## 先验收两个执行组合

在所有新视觉路由和池仍关闭时，分别运行一次拆镜候选和一次 SVG 候选，使用同一小文稿与相同画风。场景必须显式提供 `--scenario` 和 `--source-dir`；视频没有可省略场景的内置 fixture。

输入仅为 canonical UTF-8 `video-input.json`，任务仅含对应 `input_sha256`，候选场景记录文件的名称、字节数和摘要。拆镜候选可设 `max_scenes=2`；SVG 候选设 1280×720、短旁白、简单形状和少量中文。不要手填输出 SVG 或替换模型成果。

| 候选 | 真实执行 | 必须保存 |
| --- | --- | --- |
| 拆镜组合 | `video.storyboard.v1`，revision `1` | 输入、候选请求／结果／证据的摘要，实际组合与模型身份，合理的镜头说明，模型请求记录 |
| 单镜组合 | `video.scene.v1`，revision `1`，SVG | 同上，另保存生成源码、静态校验结果和中文画面截图 |

两个候选分别保留新名称和互不复用的 UID 区间。保存实际 Pod UID、节点、spec 镜像、imageID、安全上下文、所有容器的 `terminated` 状态、结束时间、退出码与 `restartCount=0`。导出候选证据后再清理本次资源。Pod 消失、Ready=false 或单行“完成”日志不构成停止证据。

管理员根据真实能力、模型往返、隔离和模型代理租约结果补齐正式验收记录，并将报告绑定到准确组合。探针输出里 `production_acceptance_created=false` 和 `production_routes_changed=false` 是预期边界；不能直接改成 true，或编一份全 true 的文件来启用路由。只开启此次验收的两个视觉组合，核对现有科研路由和 caller 未改变。

[候选探针说明](../../agent_service/docs/CANDIDATE_ACCEPTANCE_PROBE.md) 已补充视频场景及明确输入要求。执行时采用本分支实际 `--help`；视频必须显式提供 `--scenario` 和 `--source-dir`。

## 最少真实任务矩阵

业务主流程最少需要 **4 个完成的 Agent 任务**：拆镜、SVG、HTML、修订。把重启与提交恢复叠加到其中一次生成，不增加生成任务；另用 **1 个任务**验证运行中取消。

如果两个视觉组合尚无真实验收，前面还需 **2 个候选任务尝试**。因此本轮按 7 个 Agent 尝试安排预算；每个候选探针还会先发 1 次真实模型连通请求。Agent 一次任务通常包含多个模型／工具回合，7 次尝试不是 7 次模型请求，也不是费用上限。候选前提已由同一准确组合的真实证据满足时，不重复支付这两次候选成本。

建议从工作台输入下面这份短文稿，并在画风说明中明确“本次严格拆成两镜，第一镜是文稿到镜头，第二镜是候选到人工采用；深色背景、大号中文、简单图形，不新增事实”。这是一份验收文稿，生成结果仍必须来自真实模型：

> 文稿制作画面分两步：先整理成镜头说明，再由通用 Agent 生成 SVG 或 HTML。生成结果先成为候选，用户预览、修改并明确采用后，才导出素材。今天只演示这个流程，不包含配音或 MP4。

本轮将工作台“最多镜头”设为 2；该整数上限（1 至 12，默认 12）会固定进本次请求、输入摘要和重试意图。超过所设上限的返回结果不能保存为镜头。上限不保证模型一定返回两镜；若少于两镜，可手工补一镜来覆盖第二种格式，并在记录中说明。当前没有删除镜头接口，不通过额外付费生成去掩盖拆镜偏差。

| 操作 | 新增真实任务 | 业务检查与通过证据 |
| --- | --- | --- |
| 创建项目并自动拆镜 | 1，storyboard | 实际文稿进入 `video-input.json`，产生两镜且含义忠实；每镜旁白、视觉说明和时长可编辑。保存 operation、Job、attempt 与输入摘要的关联。 |
| 第一镜生成 SVG | 1，scene | 请求格式为 SVG，真实成果通过停止证明、manifest 和源码校验后只创建 V1 候选；未自动采用。检查 1280×720 画面、中文、层级、对齐、裁切与内容表达。此任务承载下节的提交恢复检查。 |
| 第二镜生成 HTML | 1，scene | 手工将第二镜格式设为 HTML 后生成。保存 HTML/CSS 源码与截图；静态页面正常显示，无外部字体／图片依赖，源码通过现有白名单，不要求模型使用被禁止的脚本或 CSS at-rule。 |
| 采用与第一次导出 | 0 | 尚有未采用镜头时导出应被拒绝；明确采用两个 V1 后下载 ZIP，核对 manifest 的顺序、版本、时长、文件摘要。断网打开独立播放器，两个镜头能切换，源码与工作台对应。 |
| 运行中取消临时项目的生成 | 1，scene | 在另一个手工单镜项目中执行，观察实际开始／模型请求受理后取消。保留停止、计费和无候选证据；不要破坏已经制作好的两镜项目。安排在下面的修订之前，以修订成功确认执行槽位恢复。 |
| 批注修订第一镜 | 1，scene | 先采用 SVG V1，选中 V1 输入具体改动，如“标题加大、将连接箭头改为橙色，保持含义”。输入携带 V1 的完整 `base_source`；产生 V2，parent 指向 V1。V1 源码保持原摘要，当前采用仍为 V1，正在看的历史预览不跳走。 |
| 修订后再次导出 | 0 | 未采用 V2 时，导出仍包含原 SVG V1 和 HTML V1；明确采用 V2 后，只有第一镜版本／源摘要改变。比较 manifest 与源文件摘要，不把 ZIP 时间戳引起的整体字节变化误认为版本替换。 |

候选生成成功和业务验收通过分开记录。人工至少确认文字无缺字、核心信息可读、不遮挡、不越界、图形关系符合文稿，修订确实表达了批注。如果源码通过校验但画面不可用，记录失败画面及原因，不写“质量通过”。这一次短样本只能证明可用性和样本耗时，不能推导批量制作速度或百分位延迟。

## 每个真实 Job 的统一取证

使用该业务 caller 读取实际 Jobs API，保存脱敏快照及其摘要。凭据、会话 cookie 和 CSRF 不进入文档、终端报告或截图。

1. operation 对应唯一 `video-<operation-id>` 幂等键、`video:<operation-id>` business_ref 和实际 Job。保存原始输入摘要与本次 execution deadline；不能通过本地 fixture 的假 Job 替换它。
2. Job 完成时读取 `GET /v1/jobs/{job_id}`：核对 `state=completed`、目标 profile／revision、实际引擎／镜像／组合 pins、attempt ID 和 fence。`stop_proven` 必须为 true，停止证明绑定同一 attempt／fence，并有请求／结果摘要、非空 writer 资源和真实观测时间。
3. 读取 `/artifact-manifest`，清单绑定同一 Job／attempt，仅有 `video-result.json`。重算 canonical 清单 SHA-256，对上 Job 的 `artifact_manifest_sha256`；下载产物后重算字节数与 SHA-256，确认 kind、输入摘要、结果格式及源码。
4. 业务最终只保存通过上述检查的候选。保留候选版本 ID、source SHA-256、是否采用与人工画面结论。`publication_authorized=false` 仍是正确结果，采用由工作台用户明确操作。
5. 对实际 Worker 资源保存控制面已经确认的 Pod 停止观测，或在清理前现场导出。将 resource ID 与真实 Pod UID 对应；已删除且没有停止记录时，不补写一个“terminated”结论。

独立候选探针结果不能替代这组公开 Job、停止证明和 manifest 证据。目前尚没有视频业务的这组真实证据。

## 将取消和恢复放进本轮任务

**提交响应丢失与重启恢复：**在第一镜 SVG 任务的工作台到 Agent 接口之间，使用仅作用于这个新业务实例的一次性受控转发，允许上游受理 POST，再丢弃这一次响应。不要改生产全局网络、关闭科研 Agent，或直接修改业务数据库制造状态。

受理后保留同一 PVC，重启工作台。应看到它通过 `/v1/jobs/by-idempotency/video-<operation-id>` 找回原 Job，随后收取同一成果。验收转发记录须证明 Jobs POST 只有一次，恢复使用 GET；同一 operation 只有一个 Job、一个执行 attempt，业务版本仅增加一次。原 attempt 自然继续多个工具回合不算重复尝试，不能用“恢复前后请求总数不变”作为判据。

如果只做“已知 job_id 的普通重启”，只能证明轮询恢复，不能把“提交响应丢失恢复”一起勾选。浏览器关页／刷新也不能替代业务服务器恢复。目前没有已执行的受控丢响应记录；一次性转发和脱敏取证工具仍待准备。

**运行中取消：**临时项目的任务确认已经执行后，从工作台点击取消。记录请求时间、`cancelling`、远端 `cancelled`／`timed_out` 终态及停止证明、实际 Pod 停止与槽位释放时间。最终该任务不产生可采用的新候选，已有项目和版本不改变，随后原项目修订能正常执行。

若取消发生在远端完成之后，记录为完成竞态，并核对结果未被误采用；它不证明“运行中取消”成功。若在启动前就取消且返回 `not_started`，它不证明“已运行进程停止”成功。`quarantined` 或无法确认停止时保留异常和资源，不清除记录去重试。运行取消需要的额外尝试单列费用，不用重复点击来凑成功。

候选探针已有的真实租约撤销，与生产 Job 的取消／超时证据分别记录。生产超时若没有同一部署身份的真实证据，仍列未验证；取消通过不能替代超时通过。验证队列中到期可以不发模型请求，但要验证已运行任务的超时停止，可能另需一次有界真实尝试，不能隐瞒在最小任务预算外。

## 耗时与费用怎样记

对每个候选和业务任务记录：操作点击时间、业务持久化时间、Agent `created_at`、`job.starting`／`job.running`／终态事件时间、writer 停止时间、工作台候选首次可见时间。时钟需能对齐，浏览器记录同时保留持续时间。分别报告排队／冷启动、执行、收集入库和用户等待，不把 2 秒轮询间隔算成模型执行时间。

按实际 attempt 汇总模型代理的请求状态、provider/model、token、缓存 token 和已知费用。候选探针的连通请求计入成本，取消尝试也计入，重放缓存不能重复算作新的上游调用。请求受理不明确时保留“不确定”，不把它计成零次。

当前工作台公开 operation 只有状态、错误和 job_id，没有耗时／费用页面；Pi 完成结果也可能 `usage=null`。需由管理员从 Agent／模型代理或已有模型网关按 attempt 导出脱敏账目，必要时从保存的 completed 响应提取用量。不要直接公开包含文稿或凭据的原始数据库／响应。若要估算费用，附价格来源、日期、模型、缓存计价规则和币种；缺少用量或价格则标“费用未知”，不可写 0 元。

| 每项必填 | 记录内容 |
| --- | --- |
| 身份 | 项目／镜头／operation／Job／attempt、profile revision、模型、发布 digest |
| 时间 | 上述时间点、用户等待秒数、排队和执行的区分；取消另记从点击到确认停止的时间 |
| 计费 | 实际上游请求数及不确定数、输入／输出／缓存 token、实测或估算金额、价格来源、缺失项 |
| 成果 | 输入／manifest／源码摘要、截图、V1/V2 与采用关系、人工通过或失败原因 |
| 停止和恢复 | 停止证明、Pod 观测、原 Job 恢复记录、POST 次数、无额外业务版本的检查 |

## 上线结论与留存

每轮使用独立受控目录，例如 `.runtime/video-acceptance/<运行标识>/`，保存简短结果表、脱敏状态／事件／manifest、输入和成果摘要、画面截图及导出包。含正文的材料按业务数据保护，不将 token、CSRF 或原始运行数据库提交 Git。清理候选资源前先保存证据；远端输入／产物按明确保留策略处理，仍在引用或隔离中的资源不强删。

只有实际登录入口、专用视觉路由、四步真实制作、真实采用与导出、取消恢复、持久化和账目观测均有对应证据，才记录“本轮上线验收通过”。超时、费用缺失或其他未验证项原样列出，并说明对上线判断的影响。不能仅凭“容器 Ready”“候选探针 completed”或一张漂亮截图宣布整项完成。

当前以上真实模型与正式入口证据均待取得。本文未增加完成项，也不触发部署、模型调用、正式验收登记或主线合并。
